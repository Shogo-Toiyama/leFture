# Android Gradle upgrade validation

An isolated checkout of the app at the same Git revision was used with Flutter 3.50.0 and JDK 17. The candidate used Gradle 9.3.1, AGP 9.1.1, Kotlin Gradle Plugin 2.4.10, and the legacy Kotlin and DSL compatibility flags added by Flutter. Test release builds use the local debug signing configuration. The original project retains its existing release signing configuration.

The first candidate passed Flutter's version check with deprecation warnings and failed Gradle Kotlin script compilation after 119.9 seconds. The old Android extension accessor and Kotlin JVM target DSL were reported as errors. The follow-up attempt uses the public application extension and Kotlin compiler options, with JVM target 11 preserved.

With those changes, an offline run of `:app:processReleaseMainManifest` passed in 51 seconds. The merged manifest declares package `com.lefture.app`, min SDK 24, target SDK 36, and 15 permissions including microphone, notifications, and the microphone foreground service. A manifest from the previous distributed release was unavailable for comparison. The candidate still pins NDK 27.0.12077973. Flutter warned that multiple installed plugins request NDK 28.2.13676358. Flutter also warned that its currently recommended Gradle, AGP, and Kotlin versions exceed the versions in this minimum-version candidate.

The full APK build then failed in Java plugin registration after 345.7 seconds because the installed `file_picker` 11.0.2 skips applying its Kotlin plugin in AGP 9 while the project globally disables built-in Kotlin. The AGP 9.1.1 distribution did not resolve the module-level built-in Kotlin plugin ID. Applying the existing Kotlin Gradle Plugin to just the file picker and setting its Kotlin target to the module's Java target (17) produced `FilePickerPlugin.class`.

The next failure was a missing `mipmap/launch_image` resource in the original checkout. It is referenced by the launch layout but absent from the checkout and ignored by the root PNG rule. The test copy reused the app's existing launcher bitmap under the missing resource name. That test-only asset does not establish the original splash appearance.

With the test bitmap and scoped Kotlin configuration, the release APK assembled in 126.2 seconds (288.9 MB), and the release AAB assembled in 54.6 seconds (216.3 MB). APK signature verification succeeded with the test key. The APK declares arm64-v8a, armeabi-v7a, and x86_64 native code. ZIP alignment passed with 16 KiB page alignment enabled, and the load segments of all 38 packaged 64-bit libraries had at least 16 KiB alignment. An API 37 emulator accepted a fresh install. Its cold launch reported 4,980 ms, and the process and foreground activity were still present five seconds after launch. This is an emulator smoke test with no prior app installation.

## Release acceptance

1. Build the release APK and AAB. Compare the packaged manifest, package ID, SDK levels, permissions, and packaged native libraries with the last distributed release.
2. On a spare physical Android device, use the distribution channel and production signing identity to update an existing installation. Verify that sign-in state, downloaded material, and existing local records survive.
3. Run the same scenarios on the existing release and the candidate. Cover cold launch, sign-in and deep links, recording with screen lock and resumption, upload and playback, and notification delivery and opening. Cover the latest Android version and the oldest device available for testing.
4. Record the build and device test outcomes before applying the candidate configuration to the primary checkout.

No physical device was visible to ADB at the start of the experiment. No model APIs or tokens were used, and the model cost was $0.

## Transfer to the main checkout

The tested Gradle, AGP, Kotlin, and file-picker settings were copied into the main checkout. The launcher bitmap was added at the missing splash resource path with a narrow Git ignore exception. The app continues to read its release signing configuration from the local `android/key.properties`.

The main checkout's AAB attempt passed Flutter's dependency version check and stopped at the release signing configuration after 16.4 seconds because `key.properties` was absent. An isolated repeat with the main checkout's exact Gradle files and an ephemeral test key produced an AAB in 20.4 seconds, and `jarsigner` verified its signature. Play upload signing and the Play update path remain untested.

After the existing upload keystore was located, the main checkout produced a signed release AAB in 164.6 seconds (216.3 MB). The merged manifest reported version name 1.1.1 and version code 503. The signer certificate matched the configured local keystore, and `jarsigner` verified the bundle. Play Console acceptance and on-device updates are still pending.
