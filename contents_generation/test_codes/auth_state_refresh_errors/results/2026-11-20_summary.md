# Auth refresh errors on the Flutter auth-state stream

The baseline test subscribes to an unfiltered broadcast stream, matching the previous app behavior. It emits a retryable transport failure and a missing refresh token error between auth-state events. Both errors reach the test's uncaught error handler. The separate case for unexpected auth errors passes.

The test then uses the production stream adapter with the same fixture. Both auth tests pass, as do the four course announcement regression tests run alongside them. Initial session, token refreshed, and signed-out events still reach the subscriber. Unexpected auth errors still propagate. The filter applies only to auth-state subscriptions. Explicit requests keep their SDK error behavior.

Both test runs use local fixtures with zero external API calls, zero model tokens, and no API charges. The separate production investigation used a read-only Supabase query to identify the SDK paths. No production samples are included here. Static analysis reports one existing Flutter Material import deprecation in the router.
