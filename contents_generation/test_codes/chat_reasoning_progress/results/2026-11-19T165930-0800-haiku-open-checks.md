# Haiku prompt replay for open checks

The original Haiku run and the new run used the same six saved excerpts. Each excerpt was the first three nonempty lines of its summary, with two trials per excerpt. Both runs requested Japanese, disabled reasoning, and used the same 96-token ceiling, streaming endpoint, and runner. Only the system prompt changed. The runner now accepts a prompt path so either variant can be reproduced.

The candidate passed the local dry run with no API calls or token spend. An initial live attempt in the restricted shell returned connection errors for all 12 attempts. The network-enabled retry produced all 12 responses below. The trials ran separately from the original baseline, so the latency difference includes run-to-run variation.

The candidate produced natural, grounded descriptions of active work in several trials. It also framed an actual open check as a question without revealing the result. The new prompt still disclosed findings. Examples included revealing that a value is unused, giving the variable classification, and stating a type mismatch. Both trials for one excerpt exceeded 60 characters after copying the full expression. No candidate was entirely in English, but one used Simplified Chinese wording. Both trials for the practice-problem excerpt mentioned how the answer would be presented, and one used two sentences on a single line. The runner's format check covers length and newlines, so it counts the latter as a pass.

This replay did not establish that the candidate reliably withholds findings. It tested only three-line excerpts, so it provides no measurement of the proposed first-line trigger or when progress would appear relative to the answer. Full responses are in the git-ignored inputs directory. No production files changed.
