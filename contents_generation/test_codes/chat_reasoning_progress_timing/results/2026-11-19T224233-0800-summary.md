# When a reasoning progress label misses the first answer text

The production answer loop was instrumented locally with the existing progress prompt, native Haiku streaming adapter, and selected answer effort from the earlier smoke test. Only synthetic questions were sent. Each time is relative to answer start. The dry run reproduced both a label that completes in time and cancellation after the first answer delta. It incurred no provider cost.

| Case | First thought | Summary starts | Summary outcome | First answer text | Time available for summary | Answer-side tokens in/out |
| --- | ---: | ---: | --- | ---: | ---: | --- |
| Weighted grade, medium 1 | 1,801 ms | 2,069 ms | Returned NONE at 2,767 ms | 3,654 ms | 1,585 ms | 8,513 / 765 |
| Weighted grade, medium 2 | 1,899 ms | 3,054 ms | Canceled with first answer text | 3,077 ms | 23 ms | 8,323 / 676 |
| Variable scope, low | 1,351 ms | 1,585 ms | Published at 2,314 ms | 3,163 ms | 1,578 ms | 8,501 / 1,087 |

The completed summary requests took 698 ms and 729 ms. Only the latter produced a presentable label. The low case had a short Japanese progress phrase. The medium case that returned NONE supplied a complete excerpt but exposed no model explanation for discarding it. The other medium case supplied its first usable excerpt only 24 ms before text, with 23 ms from actual summary start. The test did not measure the provider's private thinking duration or the browser's render time. The earlier smoke test did not record summary completion or cancellation, so its exact cause per case remains unknown.

Reported provider cost was $0.00171735. The canceled summary request may have incurred unreported provider tokens. No production code was changed.
