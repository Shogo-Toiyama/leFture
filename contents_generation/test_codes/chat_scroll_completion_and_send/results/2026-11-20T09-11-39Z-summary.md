# Chat scroll completion and send distance

Web and Flutter now follow the final layout of an answer, including citation chips and message actions, if the reader was following the bottom. On a new send, the message viewport height defines the inclusive distance for returning to the bottom. Farther up, the visible history stays in place during the send and subsequent deltas.

## Before the change

- The completion controls left 74 CSS pixels below the viewport in Chrome and 84 logical pixels below the viewport in Flutter. [Chrome baseline](2026-11-20T09-08-50-663Z-web.log) · [Flutter baseline](2026-11-20T09-08-30Z-flutter-baseline.log)
- Sending from near the bottom left 533 CSS pixels below the viewport in Chrome and 722.5 logical pixels in Flutter. The first Flutter far-position probe failed to find its fixture text. A probe tracking the visible message widget confirmed position preservation on both platform variants. [Flutter far-position baseline](2026-11-20T09-09-31Z-flutter-far-baseline.log)

## After the change

- Chrome passed all six scenarios in 1,221 ms. The full chat page and panel returned to the bottom at exactly one screen away and preserved the reader's position one pixel farther away. The existing eight-case Chrome scroll suite also passed. [New cases](2026-11-20T09-11-39-739Z-web.log) · [Existing cases](2026-11-20T09-11-39-648Z.log)
- Flutter passed all 69 conversation widget tests in about 6 seconds, including the Android and iOS scroll variants. [Flutter results](2026-11-20T09-11-39Z-flutter.log)
- The Web production build passed.

The backend sends citations in the same completion event as the final status. A read-only Supabase query confirmed a completed assistant message with a nonempty citations array and returned only a boolean to the experiment. The UI tests use synthetic conversations for predictable scroll distances. The browser and widget runners required execution outside the sandbox. No model calls, tokens, or model costs were incurred.
