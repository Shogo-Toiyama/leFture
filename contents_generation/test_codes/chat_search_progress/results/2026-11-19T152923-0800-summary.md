# Chat search progress label

The backend first emits a searching status with no target when retrieval is needed. The navigator supplies the actual search target when it has a validated operation. Before the fix, both clients displayed the lecture-note search label for the first event, even before a Web search.

The clients now use the existing localized thinking label until there is search detail. Flutter replaces the entire search state when a status event arrives, including clearing absent fields. This prevents a previous query, source type, or handle from lingering in a later status.

The baseline failed on the pending-target case in both languages on both clients. On the final version, Web passed 12 localized render assertions and TypeScript type checking. Flutter passed 28 tests, including two English and Japanese stream sequences and the existing chat state tests. Tests used local fixtures with no model or Web search charges.
