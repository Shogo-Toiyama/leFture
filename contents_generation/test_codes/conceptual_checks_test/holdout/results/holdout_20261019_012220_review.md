## なぜ分けるのか

ファイルの読み書きやネットワーク通信は、いつも同じ結果になるとは限りません。たとえば同じ処理でも、ファイルの中身や通信状態によって結果が変わります。こうした「外とのやりとり」が計算の中に混ざると、テストもデバッグも大変になります。

## なぜ中と外を分けるの？

**純粋関数**は、同じ入力を渡せば必ず同じ出力が返り、外の世界に何も影響を与えない関数のことです。たとえば足し算は、いつ何回呼んでも結果が変わりませんよね。

そこで、

- **中（core）**：計算や判断のロジックだけを純粋関数で書く → テストしやすく、動きが読みやすい
- **外（shell）**：入出力や状態の出し入れを担当する → 面倒な部分を一か所にまとめられる

という役割分担にすると、全体がすっきりします。

ちなみに、この違いは「`=`で名前を付け替えるのか」「`.`で中身をいじるのか」を見分けると整理しやすいですよ。今のイメージにこの2パターンを足せば、かなり正確に説明できると思います。

大筋はあっています。特に「com[0]は`c1`が指しているのと同じCommedianオブジェクトを指している」という見方はそのとおりです。ただ、「参照先を変える」と「中身を変える」の区別をもう少し丁寧に見ると、混乱がほどけると思います。

まず、変数やリストの要素、オブジェクトの属性は、どれも**オブジェクトへの参照（名札のようなもの）**です。`com[0]`も`c1`も、同じオブジェクトに貼られた別々の名札、と考えるとイメージしやすいです。

「中身を変える」が前の値にも響くのは、**同じオブジェクトを複数の名札が指していて、そのオブジェクトの中身を書き換えたとき**です。`c1.joke = "joke8"`のように属性を変えると、そのオブジェクトを指している`com[0]`からも同じ中身が見えます。一方で`c1 = Commedian("joke9")`のように名札そのものを付け替えると、`com[0]`は古いオブジェクトを指したままです。

```python
class Commedian:
    def __init__(self, joke):
        self.joke = joke

c1 = Commedian("joke7")
com = [c1]

c1.joke = "joke8"        # 中身を変える
print(com[0].joke)       # joke8（同じオブジェクトを見ているので反映される）

c1 = Commedian("joke9")  # 名札を付け替える
print(com[0].joke)       # joke8（com[0]は古いオブジェクトのまま）
```

もう一つ注意したいのは、`"joke7"`のような文字列（str）は**変更不可能（イミュータブル）**だということです。文字列の中身そのものは書き換えられないので、`joke`を「変えた」ように見えるときは、実際には属性が別の文字列オブジェクトを指すように付け替えられています。だから、文字列に関しては「中身を変えたら前の値も変わる」は起きません。リストやCommedianのような自作オブジェクトは変更可能なので、中身を変えると共有している全員に影響します。

まとめると、「Pythonはすべて参照」は正しいのですが、効いてくるのは「同じオブジェクトを複数の名札が指していて、そのオブジェクトが変更可能なとき」です。ここが分かると、さっきのイメージ図もかなりしっかりしたものになるはずです。


### 案B (回1)

その理解で合っています！ `com[0]`は`c1`と同じCommedianオブジェクトを指していて、`c1`はそのオブジェクトを指す名前、`joke`属性は`"joke7"`の文字列オブジェクトを指している。矢印の向きまで正確に描けています。

「参照先を変えたら中身も変わる」は、実は2種類の操作を混ぜて考えると整理しやすくなります。

- **オブジェクトの中身を書き換える**: `c1.joke = "joke8"` のように、同じCommedianオブジェクトの属性を変える操作です。このオブジェクトを指している`com[0]`からも、同じ中身が見えます。
- **変数の指す先を付け替える**: `c1 = Commedian("joke9")` のように、名前`c1`を別のオブジェクトに向け直す操作です。`com[0]`は古いオブジェクトを指したままなので、変わりません。

```python
class Commedian:
    def __init__(self, joke):
        self.joke = joke

c1 = Commedian("joke7")
com = [c1]

c1.joke = "joke8"          # 中身を書き換え
print(com[0].joke)         # joke8（com側からも見える）

c1 = Commedian("joke9")    # 名前を付け替え
print(com[0].joke)         # joke8のまま（古いオブジェクトを指している）
```

ちなみに、`"joke7"`という文字列そのものは書き換えられません。文字列は変更不可能（イミュータブル）なので、`joke`属性に新しい文字列を入れ直すことで「中身が変わった」ように見えます。

つまり、先生の「参照」の話と今の図は矛盾していません。同じオブジェクトを複数の名前やリストが共有しているときに、その中身を変えると全員に見える、というのが核心です。このイメージを持っておくと、リストのコピーや関数に引数を渡したときの挙動も読みやすくなるはずですよ。


### 案B (回2)

そのイメージで合っています！`com[0]` は `c1` と同じ Commedian オブジェクトを指していて、`c1.joke` はその中の `"joke7"` という文字列オブジェクトを指している、という理解で大丈夫です。

ここで大事なのが、「変数」と「オブジェクト」は別物だということです。変数名は中身につけた**付箋**のようなもので、`c1` や `com[0]` は「このオブジェクトを見てね」という目印にすぎません。だから、**付箋の貼り先を変えても、貼られていた先のオブジェクトは変わりません。**

```python
class Commedian:
    def __init__(self, joke):
        self.joke = joke

c1 = Commedian("joke7")
com = [c1]           # com[0] も同じ Commedian を指す

c1 = Commedian("joke8")   # c1 の付箋を新しいオブジェクトに貼り替え
print(com[0].joke)        # joke7のまま（com[0]は古いオブジェクトのまま）
```

---

一方で、**同じオブジェクトの中身を書き換える**（`c1.joke = "joke8"` のように属性を変える）場合は、そのオブジェクトを指しているすべての参照から同じ中身が見えます。`com[0]` も `c1` も同じ Commedian を見ているので、どちらからでも `joke8` が見えるわけです。

ただ、ここには少しだけ注意点があります。Python の文字列（str）は**変更できないオブジェクト**なので、`"joke7"` という文字列オブジェクトそのものは書き換えられません。`c1.joke = "joke8"` としても、`joke` が指す先が別の文字列オブジェクトに替わるだけで、`"joke7"` 自体は残ったままです。ですから「中身を変えたら前の値も変わる」が起きるのは、書き換え可能なオブジェクト（リストや自作クラスのインスタンスなど）の場合、と覚えておくとすっきりすると思います。

この区別がつくと、参照の挙動がかなり予測しやすくなりますよ。
