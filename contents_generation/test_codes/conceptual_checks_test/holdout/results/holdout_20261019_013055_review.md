## `[1, 2, 3] : [4, 5, 6]` がダメな理由

`:`は左に「1個の要素」、右に「リスト」を置く約束になっています。

```haskell
1 : [2, 3]        -- [1,2,3]  OK
```

ここで左の`[1, 2, 3]`は「リスト」なので、`:`から見ると「要素1個」ではなく「リスト1個」です。右の`[4, 5, 6]`は整数のリストなので、要素の型が合わなくな...

*ほぼ合っている*

**ユーザー**: ありがとう。

- **if-else**：「この式が真か偽か」で分けます。
- **ガード（`|`）**：「この条件が真か」で分けます。if-else を縦に並べた書き方です。
- **パターンマッチング**：「引数の**形**（0なのか、リストの空か、先頭と残りに分けられるか）」で分けます。


## パターンマッチングならではの違い

違いが出るのはリストのような「中身を取り出したいとき」です。

```haskell
-- if-else版
myLength xs = if null xs then 0 else 1 + myLength (tail xs)

-- パターンマッチング版
myLength []     = 0
myLength (_:xs) = 1 + myLength xs
```

パターン版の `(_:xs)` は、「空でないか調べる」と「先頭を捨てて残りに `xs` と名前をつける」を一度にやっています。if-else版では、判定の `null xs` と、取り出しの `tail xs` を別々に書く必要があります。

つまり、**分岐する + 中身に名前をつけて取り出す**を1行でまとめられるのがパターンマッチングの良さです。

## H8 [B] パルスを送るだけでsinc?
*本当にずれている。訂正は残したい*

**ユーザー**: おおー、ほんとに池に石を投げた時のイメージだね。
しかもパルスを投げたら必ずこれになるんだったら、ネットワークの世界では特別な形の波形を作ろうとしなくても、パルスを送るだけでちゃんと1/2Bのゼロ点が現れてくれるってことだよね？

**前の本番の回答(参考)**: おっ、池の波紋のたとえがしっくりきたみたいでよかった！

ただ、実はここがちょっと惜しいポイントで、**「パルスをただ普通に送るだけで、完璧なSinc関数になってくれるわけではない」**んだよね。

そこにはいくつか現実の壁があるんだ：

1. **「理想的な帯域制限」なんて現実にはない**
   通信路やフィルターが、スパッと一瞬で特定の周波数で区切られるような「理想的な矩形（くけい）特性」を持っているわけじゃないんだ。現実のフィルターはなだらかにしか遮断できない。
2. **無限に広がっちゃう**
   Sinc関数は水面の波紋みたいに、理論上は時間的にも無限の遠くまで裾野が広がっている。...


### 案A (回1)

その直感はかなり近いです。ただ、「どんなパルスでも必ず」とまでは言えないので、そこだけ補足させてください。

**ゼロ点が出てくる理由**

理想的な帯域制限のフィルタ（通せる周波数の幅が B のもの）にごく短いパルスを通すと、出力は sinc 関数という、中央が一番高くて左右に振動しながら減っていく形になります。この sinc の隣の山との間隔がちょうど 1/(2B) で、山の位置でほかのパルスの影響がゼロになります。だから 1/(2B) ごとに信号を取り出すと、隣のパルスに邪魔されません。

**「どんなパルスでも」ではない点**

ここが大事なところです。ゼロ点が出るのは、主に次の二つが成り立つ場合です。

- パルスが十分に短い（インパルスに近い）
- 通り道が理想的な帯域制限をかけている

幅の広い四角いパルスを同じフィルタに通すと、出力はきれいな sinc にはならず、ゼロ点もぴたりとは揃いません。なので「パルスを送るだけで必ず 1/(2B) のゼロ点が現れる」とは言い切れないんです。

**実際のネットワークでは**

理想のフィルタは現実には作れないので、実際の通信では、ゼロ点を持つ形（レイズドコサインなど）のパルスをわざわざ設計して使うことが多いです。そうしておくと、回線の少しのずれにも強くなります。つまり、特別な波形を作らなくていいというより、ゼロ点を狙って波形を整えるのが実務の考え方だと思ってもらうとよいです。

ちなみに、講義で使った前提（パルスの幅や、フィルタの形がどうだったか）によって答えの細部が変わるので、そこは講義の該当部分と照らし合わせてみてくださいね。


### 案A (回2)

池に石を投げた波紋のイメージ、いい例えですね。ただ、結論は半分だけ当たっています。

**当たっている部分**: 帯域幅Bの理想的な低域フィルタ（ちょうどB Hzまでしか通さない通信路）に理想的なパルス（インパルス）を入れると、出力は sinc 関数という波形になります。この波形は 1/(2B) 秒ごとに0を通るので、特別な形を自分で作らなくても、帯域の制限がそのまま「0の位置」を決めてくれるわけです。

**注意したい部分**: 「どんなパルスを投げても必ずこうなる」わけではありません。出力の形は入力パルスと通信路の両方で決まるので、0の位置は**通信路の帯域**によって決まる、と捉えるのが正確です。また、理想的な帯域制限の通信路は現実にはないので、実際には sinc の裾が長くて扱いにくい問題も出てきます。そこで、裾を短く抑えた raised cosine のような波形が使われることが多いです。
