# Course announcement provider lifecycle

The Flutter experiment runs the three production provider functions with a controlled lecture stream and replaces their Riverpod Ref before the first lecture emission. It also checks initial output through the three generated providers with local test fixtures.

| Run | Disposed Ref cases | Mounted case |
| --- | --- | --- |
| Before | 3 failed with `UnmountedRefException` | Passed |
| After | 3 passed, with each stream ending without an error or value | Passed |

The fix checks `ref.mounted` immediately after waiting for the first lecture list. Static analysis of the provider source and generated file reported no issues. The run used local fixtures for timing control, made zero external API calls, consumed zero model tokens, and incurred no API charges. The test runner timestamps have one-second resolution and do not measure application latency.
