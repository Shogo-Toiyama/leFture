## 1つ目：map / filter / reduce 🧺

この3つは、**リストを流れ作業のベルトコンベアに乗せる道具**だと思うと分かりやすいです。

- **map**：全部に同じ加工をする（例：全員の点数を2倍にする）
- **filter**：条件で選別する（例：偶数だけ残す）
- **reduce（Haskellでは foldl）**：全部を1つの値にまとめる（例：合計を出す）

```haskell
map (*2) [1,2,3,4]     -- [2,4,6,8]
filter even [1,2,3,4]  -- [2,4]
foldl (+) 0 [1,2,3,4]  -- 10
```

3つをつなげると、こんな流れになります。

```
[1,2,3,4]
   │ filter even
   ▼
[2,4]
   │ map (*2)
   ▼
[4,8]
   │ foldl (+) 0
   ▼
12
```

ポイントは、**map は長さを保つ、filter は減らすことがある、foldl は1つの値になる**という違いです。型で書くと、`map :: (a -> b) -> [a] -> [b]`、`filter :: (a -> Bool) -> [a] -> [a]`、`foldl :: (b -> a -> b) -> b -> [a] -> b` です。

foldlは「アキュムレータ（途中経過を入れる箱）」を持って進みます。`foldl (+) 0 [1,2,3]` は `((0+1)+2)+3` と左から順にまとめる、と追うと動きが見えてきますよ！💡

## 🔍 1番目の概念：map / filter / reduce

まずは一番基本の3兄弟から、じっくりいきましょう！🎉

**3つの役割はこうです。**

- **map**：リストの**全要素に同じ変換**をかける（形はそのまま、中身が変わる）
- **filter**：条件に合う要素だけを**残す**（数は減るかもしれない）
- **reduce（Haskellでは foldr / foldl）**：リスト全体を**1つの値にまとめる**

```
[1, 2, 3, 4]  ──filter even──►  [2, 4]  ──map (*10)──►  [20, 40]  ──foldr (+) 0──►  60
```

型で書くと、役割がもっとはっきりします。

```haskell
map    :: (a -> b) -> [a] -> [b]
filter :: (a -> Bool) -> [a] -> [a]
foldr  :: (a -> b -> b) -> b -> [a] -> b
```

ポイントは、**`map` と `filter` は「リストを返す」けど、`foldr` は「1つの値を返す」**ことです。この違いが、テストで「最終的な型は何？」と聞かれたときの答えを決めます。

そして `foldr` の動きを一歩ずつ見ると、こんな感じです。

```
foldr (+) 0 [20, 40]
= 20 + (40 + 0)
= 20 + 40
= 60
```

右から順に畳み込んでいくイメージですね。🌀 `foldl` は左から畳むので、同じ `(+)` でも**かっこの付き方が変わる**と覚えておくと便利です。

Part Bの他言語のコードも、基本は同じ「filter → map → reduce」の流れです。読むときは、**データがどの順番で流れていくか**を矢印でたどると、スッと読めるようになりますよ！💪

## ① 型の「矢印」は右から読む ➡️

```haskell
map :: (a -> b) -> [a] -> [b]
```

矢印 `->` は「入力から出力へ」の印です。大事なのは、**一番右が最終的な答え**だということ。

```
(a -> b)  →  [a]  →  [b]
 変換関数    リスト    結果のリスト
 ↑ 1つ目の引数  ↑ 2つ目の引数   ↑ 戻り値
```

`a -> b -> c` は `a -> (b -> c)` と同じ意味です。つまり「`a` を受け取ると、`b -> c` の関数が返ってくる」んです。ADVHASKELL4のカリー化とつながっていますね 🍰

---

## ② 型変数と具体的な型を見分ける 🔍

```
Int, Bool, Char   → 具体的な型（大文字で始まる）
a, b, c           → 型変数（小文字）。「何でもいい型」の場所取り
[a]               → 要素の型が a のリスト
(a, b)            → 2つの値の組（タプル）
Maybe a           → a の値か、何もない状態
```

`a` は「どの型でもOK」という意味です。`map` の `a` と `b` は、同じ型でなくても構いません。

---

## ③ 関数から型を書いてみる ✍️

関数の中身を見て、**入力は何か・出力は何か**を決めます。

```haskell
add x y = x + y
```

`x` と `y` は `+` で足せる数なので、型は次のようになります。

```haskell
add :: Int -> Int -> Int
```

もっと一般的に書くと `Num a => a -> a -> a` です。`Num a =>` は「`a` は数として扱える型」という条件のことです。

---

## ④ 部分適用すると型も変わる 🧩

```haskell
add 3 :: Int -> Int
```

`add :: Int -> Int -> Int` に1つ引数を渡すと、残りの `Int -> Int` が残ります。引数を1つずつ減らしていくと、型の右側だけが残っていくイメージです。

## 型シグネチャを読む3ステップ 📖

```haskell
map :: (a -> b) -> [a] -> [b]
```

1. **矢印 `->` で区切る**：一番右が「戻り値の型」、それ以外が「引数の型」です。ここでは `[b]` が戻り値です。
2. **括弧 `( )` は1つのかたまり**：`(a -> b)` は「関数を1つ」という意味で、左から1番目の引数になります。
3. **小文字の `a`、`b` は「何でもよい型」**：具体的な型は決まっていません。同じ文字は同じ型を指します。

```
(a -> b)   ：変換関数（a を b に変える）
  ↓ 渡す
[a]        ：入力のリスト
  ↓ 結果
[b]        ：変換後のリスト
```

## `->` は右結合 🔗

`a -> b -> c` は `a -> (b -> c)` と同じ意味です。つまり「`a` を受け取ったら、`b` を受け取って `c` を返す関数」を返す、という形になります。ADVHASKELL4のカリー化とつながっていますね！

## 型の読み書きでよく出る形 ✍️

- `filter :: (a -> Bool) -> [a] -> [a]`：条件関数を取り、同じ型のリストを返す
- `foldr :: (a -> b -> b) -> b -> [a] -> b`：`b` を初期値・結果の型として使う

型を書くときは、**値を実際に入れてみて合うかどうか**を確かめると安心です。
