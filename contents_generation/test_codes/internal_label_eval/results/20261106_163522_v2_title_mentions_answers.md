## 🎯 1つ目：map / filter / reduce

まずはこの3つを、**「データを流すベルトコンベア」**でイメージしてみてください！🏭

- **map**：全要素に同じ変換を1回ずつかける（全員に同じ作業をする）
- **filter**：条件に合うものだけ残す（ふるいにかける）
- **reduce / foldr / foldl**：全部まとめて1つの値にする（雪だるま式に集める）

```
[1, 2, 3, 4, 5, 6]
   │ filter even      ← 偶数だけ残す
[2, 4, 6]
   │ map (*10)        ← 全部10倍
[20, 40, 60]
   │ foldr (+) 0      ← 全部足す
120
```

Haskellで書くとこうなります。

```haskell
map (+1) [1, 2, 3]        -- [2, 3, 4]
filter even [1 .. 6]      -- [2, 4, 6]
foldr (+) 0 [1, 2, 3]     -- 1 + (2 + (3 + 0)) = 6
foldl (+) 0 [1, 2, 3]     -- ((0 + 1) + 2) + 3 = 6
```

型を見ると、役割がはっきり分かります。試験でも型から考えると強いですよ💪

```haskell
map    :: (a -> b) -> [a] -> [b]
filter :: (a -> Bool) -> [a] -> [a]
foldr  :: (a -> b -> b) -> b -> [a] -> b
```

ちなみに、他の言語でも名前が違うだけで同じ発想です。Ruby の `select` は filter、`inject` は reduce にあたります。Rust の `fold`、TypeScript の `reduce` も同じ仲間です！

## 🔍 1番目の概念：map / filter / reduce

まずは一番基本の3兄弟から、じっくりいきましょう！🎉

**3つの役割はこうです。**

- **map**：リストの**全要素に同じ変換**をかける（形はそのまま、中身が変わる）
- **filter**：条件に合う要素だけを**残す**（数は減るかもしれない）
- **reduce（Haskellでは foldr / foldl）**：リスト全体を**1つの値にまとめる**

```
[1, 2, 3, 4]  ──filter even──►  [2, 4]  ──map (*10)──►  [20, 40]  ──foldr (+) 0──►  60
```

型で書くと、役割がもっとはっきりします。

```haskell
map    :: (a -> b) -> [a] -> [b]
filter :: (a -> Bool) -> [a] -> [a]
foldr  :: (a -> b -> b) -> b -> [a] -> b
```

ポイントは、**`map` と `filter` は「リストを返す」けど、`foldr` は「1つの値を返す」**ことです。この違いが、テストで「最終的な型は何？」と聞かれたときの答えを決めます。

そして `foldr` の動きを一歩ずつ見ると、こんな感じです。

```
foldr (+) 0 [20, 40]
= 20 + (40 + 0)
= 20 + 40
= 60
```

右から順に畳み込んでいくイメージですね。🌀 `foldl` は左から畳むので、同じ `(+)` でも**かっこの付き方が変わる**と覚えておくと便利です。

Part Bの他言語のコードも、基本は同じ「filter → map → reduce」の流れです。読むときは、**データがどの順番で流れていくか**を矢印でたどると、スッと読めるようになりますよ！💪

## ① 型シグネチャの読み方 📖

`::` の右側が型です。`->` は「引数を1つ受け取って、次の型を返す」という矢印です。

```haskell
map :: (a -> b) -> [a] -> [b]
```

左から順に、こう読めます。

```
(a -> b)  ：変換関数（aを受け取ってbを返す）
[a]       ：aのリスト
[b]       ：結果はbのリスト
```

小文字の `a`、`b` は「どんな型でもOK」という**型変数**です。大文字の `Int` や `Bool` は、決まった型を表します。

---

## ② `->` は右から結合する 🔗

`->` は右側にまとまって読まれます。だから、次の2つは同じ意味です。

```haskell
add :: Int -> Int -> Int
add :: Int -> (Int -> Int)
```

つまり `add` は「Intを受け取り、Intを受け取ってIntを返す関数」を返す、という形なんです。前にやったカリー化の話とピッタリつながりますね！🎁

---

## ③ 型から「何を受け取るか」を読む 🎯

```haskell
foldr :: (a -> b -> b) -> b -> [a] -> b
```

- 第1引数：`a` と `b` を受け取り `b` を返す関数
- 第2引数：初期値の `b`
- 第3引数：`a` のリスト
- 結果：`b`

型変数が同じ `b` なら、「同じ型である」という約束になっています。ここが読めると、「この引数に何を渡せばいいか」が一目で分かります。

---

## ④ 型を書く・推論する 🛠️

関数の定義から型を推論するときは、「引数の型」と「戻り値の型」をそれぞれ決めていきます。

```haskell
double x = x * 2
```

`*` は同じ型の2つの数を扱うので、`x` は数値型です。結果も同じ数値型なので、型は次のようになります。

```haskell
double :: Num a => a -> a
```

`Num a =>` は「`a` は数値型であること」という条件です。この条件を読み落とすと、テストで間違えやすいので注意しましょう。

- 小文字は型変数、大文字は具体的な型
- 同じ型変数は同じ型を表す
- `Num a =>` のような条件（制約）も型の一部

## 型シグネチャを読む3ステップ 📖

```haskell
map :: (a -> b) -> [a] -> [b]
```

1. **矢印 `->` で区切る**：一番右が「戻り値の型」、それ以外が「引数の型」です。ここでは `[b]` が戻り値です。
2. **括弧 `( )` は1つのかたまり**：`(a -> b)` は「関数を1つ」という意味で、左から1番目の引数になります。
3. **小文字の `a`、`b` は「何でもよい型」**：具体的な型は決まっていません。同じ文字は同じ型を指します。

```
(a -> b)   ：変換関数（a を b に変える）
  ↓ 渡す
[a]        ：入力のリスト
  ↓ 結果
[b]        ：変換後のリスト
```

## `->` は右結合 🔗

`a -> b -> c` は `a -> (b -> c)` と同じ意味です。つまり「`a` を受け取ったら、`b` を受け取って `c` を返す関数」を返す、という形になります。ADVHASKELL4のカリー化とつながっていますね！

## 型の読み書きでよく出る形 ✍️

- `filter :: (a -> Bool) -> [a] -> [a]`：条件関数を取り、同じ型のリストを返す
- `foldr :: (a -> b -> b) -> b -> [a] -> b`：`b` を初期値・結果の型として使う

型を書くときは、**値を実際に入れてみて合うかどうか**を確かめると安心です。
