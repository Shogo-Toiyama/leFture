## ① Map, filter, reduce をていねいに 🏭

リストに対する「よくある3つの処理」です。ベルトコンベアで考えると分かりやすいですよ。

```
[1, 2, 3, 4, 5, 6]
      │ filter（偶数だけ残す）
      ▼
[2, 4, 6]
      │ map（全部を ×10 する）
      ▼
[20, 40, 60]
      │ reduce（全部足して1つにする）
      ▼
120
```

それぞれの役割はこうです。

- **map**：1つずつ変換します。要素の数は変わりません。変換後の型が変わってもOKです（文字列のリストを長さのリストに変えるなど）。
- **filter**：条件を満たすものだけ残します。要素の型は変わりません。
- **reduce**：リスト全体を1つの値にまとめます。Haskellでは `foldl` や `foldr` がこの役です。

`foldl` と `foldr` は、まとめる向きが違います。足し算だけなら結果は同じですが、引き算だと結果が変わります。

```haskell
foldl (-) 0 [1,2,3]  -- ((0-1)-2)-3 = -6
foldr (-) 0 [1,2,3]  -- 1-(2-(3-0)) = 2
```

演習の問題1は、「どの形の処理か」を見抜くのが最初の一歩です。全要素に同じ操作をする話なのか、条件で残す話なのか、全体を1つにまとめる話なのかを、まず判断してみてください。Part Bの TypeScript、Ruby、Rust のコードも、同じ filter → map → reduce の形になっています。言語が変わっても、左から右へ1段ずつ読めば大丈夫です！

今の時点で見えているのは講義の見出しまでなので、ここは一般的な解説になっています。ここまでで「どの処理か」を見抜けるようになったら、問題1はばっちりです！💪

## 🔍 1番目の概念：map / filter / reduce

まずは一番基本の3兄弟から、じっくりいきましょう！🎉

**3つの役割はこうです。**

- **map**：リストの**全要素に同じ変換**をかける（形はそのまま、中身が変わる）
- **filter**：条件に合う要素だけを**残す**（数は減るかもしれない）
- **reduce（Haskellでは foldr / foldl）**：リスト全体を**1つの値にまとめる**

```
[1, 2, 3, 4]  ──filter even──►  [2, 4]  ──map (*10)──►  [20, 40]  ──foldr (+) 0──►  60
```

型で書くと、役割がもっとはっきりします。

```haskell
map    :: (a -> b) -> [a] -> [b]
filter :: (a -> Bool) -> [a] -> [a]
foldr  :: (a -> b -> b) -> b -> [a] -> b
```

ポイントは、**`map` と `filter` は「リストを返す」けど、`foldr` は「1つの値を返す」**ことです。この違いが、テストで「最終的な型は何？」と聞かれたときの答えを決めます。

そして `foldr` の動きを一歩ずつ見ると、こんな感じです。

```
foldr (+) 0 [20, 40]
= 20 + (40 + 0)
= 20 + 40
= 60
```

右から順に畳み込んでいくイメージですね。🌀 `foldl` は左から畳むので、同じ `(+)` でも**かっこの付き方が変わる**と覚えておくと便利です。

Part Bの他言語のコードも、基本は同じ「filter → map → reduce」の流れです。読むときは、**データがどの順番で流れていくか**を矢印でたどると、スッと読めるようになりますよ！💪

## 🔍 型シグネチャの読み方

```haskell
map :: (a -> b) -> [a] -> [b]
```

- **`->` は「引数 → 結果」の矢印**です。右に行くほど「次に受け取るもの」「最後の結果」になります。
- **`a` や `b` は型変数**で、「どんな型でもOK」という意味です。`a` と `b` が別の文字なら、別の型でもOK、同じ文字なら同じ型である必要があります。
- **一番右が最終的な戻り値**です。ここが `[b]` なので、`map` はリストを返すと分かります。

```
map :: (a -> b)  ->  [a]  ->  [b]
        ↑            ↑        ↑
     変換関数     入力リスト  出力リスト
```

---

## 🧩 カッコで意味が変わる

```haskell
f :: a -> b -> c        -- 引数2つ、結果はc
g :: (a -> b) -> c      -- 引数は「関数」1つ、結果はc
```

`->` は右結合なので、`a -> b -> c` は `a -> (b -> c)` と同じです。だから、「1つ渡すと、残りを待つ関数が返ってくる」というカリー化の話とつながります。

## 型シグネチャを読む3ステップ 📖

```haskell
map :: (a -> b) -> [a] -> [b]
```

1. **矢印 `->` で区切る**：一番右が「戻り値の型」、それ以外が「引数の型」です。ここでは `[b]` が戻り値です。
2. **括弧 `( )` は1つのかたまり**：`(a -> b)` は「関数を1つ」という意味で、左から1番目の引数になります。
3. **小文字の `a`、`b` は「何でもよい型」**：具体的な型は決まっていません。同じ文字は同じ型を指します。

```
(a -> b)   ：変換関数（a を b に変える）
  ↓ 渡す
[a]        ：入力のリスト
  ↓ 結果
[b]        ：変換後のリスト
```

## `->` は右結合 🔗

`a -> b -> c` は `a -> (b -> c)` と同じ意味です。つまり「`a` を受け取ったら、`b` を受け取って `c` を返す関数」を返す、という形になります。ADVHASKELL4のカリー化とつながっていますね！

## 型の読み書きでよく出る形 ✍️

- `filter :: (a -> Bool) -> [a] -> [a]`：条件関数を取り、同じ型のリストを返す
- `foldr :: (a -> b -> b) -> b -> [a] -> b`：`b` を初期値・結果の型として使う

型を書くときは、**値を実際に入れてみて合うかどうか**を確かめると安心です。
