# 設計（ドラフト）

> コンセプト確定・具体化に伴い順次更新。

## 画面構造（3View構成 / LODアーキテクチャ）

ユーザー体験を「マクロ（全体）」「メソ（集合・関係性）」「ミクロ（個別詳細）」の3段階で構成する。

```
[Level 1: 銀河View (マクロ)]
  └─ ピンチイン / ズームでトランジション
[Level 2: 星座・星雲View (メソ)]
  └─ 特定の星を選択 / ズーム
[Level 3: 恒星View (ミクロ)]
```

### 1. Level 1: 銀河View（マクロ）
- **役割**: 見た目の美しさと全体の成長を楽しむ。銀河を回転させて鑑賞する。
- **機能**:
  - 全体Statsの表示（星の総数、銀河の大きさ、記録継続など）。
  - 銀河の自由回転・オートオービット（現行機能の発展）。
- **描画仕様**:
  - 個別星の厳密な座標管理・DB保存は行わない。
  - 現行のプロシージャル生成（`GalaxyConfig`）をベースとし、ユーザーの学習進度に応じてパラメータ（腕の数、星・星雲の色、厚み、輝度など）を変化させて個別性を出す。
  - 星の個別タップは行わない（タップ判定の負荷ゼロ）。

### 2. Level 2: 星座・星雲View（メソ / 仮称）
- **役割**: 意味的なつながりや自分の将来に関連する星の集合（星座・星雲）を鑑賞・確認する。
- **機能**:
  - 自由探索ではなく、**「リスト・表・カルーセル」等から特定の星座や星雲を選択**する。
  - 選択された星座・星雲にカメラがフォーカス（または画面中央にフォーカス展開）。
  - **星雲 (Nebula)**:
    - 意味的に近い星を20〜100個集めた塊。
    - 色やモヤ（ガス）の種類を動的に変え、ユニークな星雲を生成。
    - AIがその星雲に象徴的な名前を付与。
  - **星座 (Constellation)**:
    - 特に強い結びつきを持つ星5〜12個を選出。
    - 2次元平面上に座標配置して星間にエッジを結線。
    - 星座の内容・モチーフに合致した**「ネオン調の星座絵（薄く光る具象線画: ノートPC、ロボット等）」**＋AIによる命名を重畳表示。
    - **生成方式: 3段階パイプライン（後述）** により自動生成。
- **描画仕様**:
  - 銀河内部に入り込んだような背景星の空間を維持しつつ、主役の星座/星雲を際立たせる。

## 星座生成の3段階パイプライン（3-Stage Pipeline）

```
[蓄積された星群 (5〜12個)]
  │
  ▼
【Stage 1: 構想・命名役 (The Visionary)】
  星々のタイトル・物語・ベクトルを読み解き、「〇〇座（例: ノートPC座、探求のフクロウ座）」という
  象徴的な星座名・神話ストーリー・具体的なモチーフ（描くべき具象物）を決定。
  │
  ▼
【Stage 2: 作画役 (The Celestial Artist)】
  決定された具象モチーフに基づき、ネオン調のシンプルなSVG線画（パスデータ）を出力。
  （※ゼロからAIが描く方式と、30〜50種の美麗モチーフテンプレートから選ぶ方式の2通りを検証）
  │
  ▼
【Stage 3: 配置・結線役 (The Astrologer)】
  作画された星座絵の主要頂点（角、ヒンジ、節目、関節など）に、集まった星たち（N個）を順番・重要度順にマッピング。
  骨格となるエッジ（結線）データを生成して星座を完成させる。
  ※個別の星に「左目」などの部位名を厳密に固定する必要はなく、スロットへ自然に割り当てる。
```

### 3. Level 3: 恒星View（ミクロ）
- **役割**: 個々の学び・経験を表す「星そのもの」を詳細に見る。
- **機能**:
  - 一つ一つの星のプロファイル・詳細情報（学んだ内容、日付、元になった講義やチャットの抜粋、気づき）の確認。
  - **星の単位**: 「コンセプト1つ」「経験1つ」「物語1つ」。
  - **星の獲得経路**:
    - ① 講義の分析・生成（ベースラインとして徐々に蓄積）。
    - ② **チャットでの対話・深掘り（最も星が溜まる主力チャネル）**: 復習、新たな気づき、趣味、クラブ活動、アイデア、相談など、「その人らしさ」を言語化した時に高頻度で星が誕生。
    - ③（将来拡張）日記機能（テキスト/音声の一方通行記録＋AIフォローアップ）、音声対話（Gemini Live風）。
- **描画仕様**:
  - 静的なテクスチャ画像の固定配置ではなく、**パラメータ合成によるプロシージャル描画**。
  - パラメータ（大きさ、ベース色、光彩・コロナ、模様・テクスチャパターン、ガスの渦巻き、自転速度など）の組み合わせにより、多数のユニークな星を軽量に表現する。

## 星の抽出・生成設計（現行機能からのパイプライン）

初期フェーズ（MVP）では、**「①講義内容」** と **「②AIチャット」** の2つを星の源泉とし、既存のデータ・推論パイプラインを最大限に活用する。

```
[インプット源]
  ├─ 講義パイプライン ───→ トピック・重要コンセプトから自動抽出 (1講義あたり 1〜3個)
  └─ AIチャット ─────────→ 対話の深まり・本人の気づきから抽出 (1スレッドあたり 1〜3個)
```

### 1. 講義からの抽出（自動・ベースライン）
- **対象データ**: `lecture_topics`（トピック）、`keywords`（キーワード）、`deep_notes`（ディープノート）。
- **抽出タイミング**: バックエンドの講義生成パイプライン完了時（Pipeline Phase 終了時）。
- **抽出内容**:
  - タイトル: トピックの核心となるコンセプト（例: 「直交行列の幾何学的意味」）
  - 物語（ストーリー）: トピックの要約（`summary`）＋ディープノートの要点。
  - 元データ参照: `lecture_id`, `topic_id`
  - ベクトル: トピック内容のEmbedding（768次元）。
- **星の生成数**: 講義1本あたり 1〜3個程度（粗すぎず、細かすぎない単位）。

### 2. AIチャットからの抽出（高密度・「その人らしさ」の主力）
- **対象データ**: `chat_threads`, `chat_messages`（特にユーザー発言とAIの対話）。
- **抽出基準**:
  - 単なる事実確認（「次のテスト何日？」など）は除外。
  - **「ユーザーの感情・悩み・自己開示・深い洞察・アイデア」** が言語化された対話ブロックを検出（既存の自分像 `profile_observations` の抽出ロジックと連動）。
- **抽出タイミング**:
  - スレッドの一区切り（スレッド退出時、または一定ターン経過後のバックグラウンド処理）。
- **抽出内容**:
  - タイトル: 本人の気づき・視点を凝縮したタイトル（例: 「UIにロジックを引きずられない設計哲学」）
  - 物語: ユーザーの発言引用（`quote`）＋対話から得られた学び。
  - 元データ参照: `thread_id`, `message_id`
- **星の生成数**: 密度の濃い対話スレッドから 1〜3個。

### 3. 将来拡張（ロードマップ）
- **自由セッション録音**: 講義に限らず、「思考の独り言・アイデア出し」「TAとのディスカッション（ザワザワしたQAやまとめ）」「特別セミナー・ゲスト講義」「スライドのみの読込」など、雑多に詰め込める自由度の高い録音機能。
- **日記・ライフログ機能**: 一方通行の手軽なテキスト/音声記録＋AIからの関心フォローアップ。

## データモデル（方針）

### 1. 「大星（親星）」と「小星（従属星群）」の親子構造
2万個の星を個別のDB行としてフラットに管理するのではなく、**「主要テーマを司る大星（親）」の中に「5〜20個の小星（子）」を内包する階層構造**を採用する。

### 2. Supabase テーブル定義ドラフト (`galaxy_stars`)

```sql
CREATE TABLE public.galaxy_stars (
    id uuid DEFAULT gen_random_uuid() NOT NULL PRIMARY KEY,
    user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    
    -- 星の基本情報
    title text NOT NULL,                                -- 星の名前（象徴的コンセプト、例:「直交行列の幾何学的解釈」）
    description text DEFAULT ''::text NOT NULL,         -- 学び・気づき・ストーリーの要約
    kind text NOT NULL,                                 -- 種類: 'insight'(気づき), 'learning'(学び), 'emotion'(感情/思い), 'interest'(興味), 'experience'(経験)
    tags text[] DEFAULT '{}'::text[] NOT NULL,          -- 分野・カテゴリ・性格タグ（['software_engineering', 'math', 'philosophy'] など。星座・星雲の種）
    
    -- 出典・コンテキスト
    source_type text NOT NULL,                          -- 'lecture' | 'chat' | 'diary' | 'audio_memo'
    source_id uuid,                                     -- 元の lectures.id または chat_threads.id
    source_quote text,                                  -- 本人の生の声や講義の決定的な発言引用
    
    -- ビジュアル描画用パラメータ（恒星View・プロシージャル生成用）
    visual_attributes jsonb DEFAULT '{}'::jsonb NOT NULL,
    -- 例: { "spectral_type": "blue_giant", "color": "#38bdf8", "magnitude": 1.2, "pulsing": true }
    
    -- 小星群（子星リスト）
    micro_stars_count integer DEFAULT 0 NOT NULL,       -- 内包する小星の数（銀河のStatsカウントに加算）
    micro_stars jsonb DEFAULT '[]'::jsonb NOT NULL,     -- 子星リスト
    -- 例: [ { "name": "内積の不変性", "magnitude": 0.3, "created_at": "..." }, ... ]
    
    -- ベクトル埋め込み（星雲クラスタリング・星座判定用）
    embedding extensions.vector(768),
    embedding_model text,
    
    -- 拡張用メタデータ & ライフサイクル
    metadata jsonb DEFAULT '{}'::jsonb NOT NULL,        -- クエストIDや将来の拡張データ
    deleted_at timestamp with time zone,                -- 論理削除（ゴミ箱）
    created_at timestamp with time zone DEFAULT now() NOT NULL,
    updated_at timestamp with time zone DEFAULT now()
);

-- インデックス
CREATE INDEX idx_galaxy_stars_user_active ON public.galaxy_stars (user_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_galaxy_stars_tags ON public.galaxy_stars USING gin (tags);
CREATE INDEX idx_galaxy_stars_source ON public.galaxy_stars (source_type, source_id);
-- ベクトルインデックス（コサイン距離検索）
CREATE INDEX idx_galaxy_stars_embedding ON public.galaxy_stars 
    USING hnsw (embedding extensions.vector_cosine_ops)
    WHERE deleted_at IS NULL;
```

#### この設計のポイントとベクトルの保存先
- **ベクトルの保存先**: `knowledge_chunks` ではなく **`galaxy_stars.embedding` に直接持たせる**。
  - 星座や星雲を計算する際の「意味の近い星を集めるコサイン類似度検索」が、`galaxy_stars` 単体で `ORDER BY embedding <=> target_vector` のように一撃で超高速実行できる。
  - チャットのRAG用知識チャンク（`knowledge_chunks`）と、ユーザーの自己対話・銀河の星という異なるドメインのデータが混ざらず、設計が極めてクリーンに保たれる。
- **子星（`micro_stars`）の持たせる情報**:
  - 親星と共通（継承）: `kind`, `tags`, `source_type`, `source_id`, `occurred_at`
  - 子星が個別にフル保持:
    ```json
    {
      "id": "ms_01",
      "title": "内積の不変性",
      "description": "直交変換によってベクトルの長さと角度が保たれる性質。基底を変えても幾何学的本質が変わらないことの美しさ。",
      "visual_attributes": {
        "color": "#7dd3fc",
        "magnitude": 0.45,
        "size": 0.8,
        "pulsing": false
      }
    }
    ```
  - **容量試算**: 1子星あたり約300〜400バイト。15個の子星が入っても1行あたり約5〜6KB程度。1年分（大星1,000件）でも全体でわずか5〜6MB程度であり、DB負荷は極めて安全。
  - **描画効果**: これにより、銀河や星雲の中で「同じ親から生まれた星たち」であっても、一粒一粒が微妙に異なる色・光・大きさでキラキラと輝き、見た目の豊かさとタップしたときの図鑑体験が劇的に向上する。

## 銀河の成長ペースとバイアス制御

### 1. 1年20,000星のプログレッション曲線（数式による連続成長）
- **初期状態 (Day 1)**: バルジ（中心核）のみの小さな銀河（`diskStarCount: 0` 付近）。
- **獲得ペース**:
  - 1講義の分析: 大星 2〜4個 ＋ 小星群 ＝ **合計 30〜80星**
  - 密度の濃いチャット/日記: 大星 5〜10個 ＋ 小星群 ＝ **最大 300〜500星**
  - アプリ利用日平均: **1日 100〜300星** が蓄積され、約1年で大銀河（20,000星・太い腕・多彩な星雲）へ成熟する。
- **数式による連続成長アプローチ**:
  - 離散的な切り替えではなく、星の総数 $N$ から滑らかに各パラメータを導出する関数を定義する。
  - **初期（0〜1,000星）の急成長**: 対数カーブ等を用い、最初の数百〜千個の間に銀河半径（`radius`）が急速に広がり、腕（`diskStarCount`）が一気に芽生える演出。
  - **成熟期（1,000〜20,000星）**: 半径拡大は緩やかになり、星々の密集度・腕の厚み・星雲の量（`nebulaCount`）がじっくりと深まる。

### 2. レベル制による機能・体験アンロック
数式による連続的なビジュアル成長に加え、マイルストーンとしての「Level」を設け、機能やカスタマイズを解放する：
- **Level 1（銀河誕生期）**: 星が急激に増えていく様子をダイナミックに楽しむ初期エフェクト期。
- **Level 2（カスタマイズ解放期）**: 中心核の発光色（Core Gradient）や星雲の色味を自分好みに改造・調整できる機能がアンロック（※初期値はランダム割当、専攻固定ではなくユーザーの好みを尊重）。
- **Level 3以降（星座・星雲解放期）**: 蓄積された大星たちから、AIによる「星座」「星雲」の生成・鑑賞Viewがアンロック。

### 3. パラメータの安全性ガード（形状破壊の防止）
- `bulgeRadiusNorm` や `innerDiskHoleNorm` など、極端にいじると銀河の幾何学形状が破綻・不自然になるパラメータは、固定値または安全域（Safe Bounds）内でのみ微調整する。
- Flutter実機およびWebappの双画面で視覚的に検証しながら調整する。

### 4. 話題バイアスの制御（話題テンプレート / クエスト方式）
- **課題**: 特定のトピックについて1日で熱狂的に長文チャットをした場合、そのトピックだけに星が過剰集中し、銀河全体のバランスが崩れる。
- **解決策**:
  - 単一スレッドでの星獲得に一定の減衰（上限キャップ）を設ける。
  - **話題テンプレート（クエスト）**: 「将来のキャリアの価値観について話してみよう」「最近面白かった課外活動は？」といった多様な切り口のプロンプト・問いかけを用意し、多角的な星を獲得することで銀河の偏りを自然に中和・調和させる。

## 実装メモ: 成長数式が動かすパラメータ候補（Flutter）
現行の `GalaxyConfig`（`user_interface/lib/application/galaxy/galaxy_data_provider.dart`）には `bulgeStarCount`（5000）・`diskStarCount`（15000）・`arms`（3）・`nebulaCount` などが別々にある。成長数式は、星の総数 N からこれらを導く形になる（どれを動かすかは画面を見ながら決める）。
