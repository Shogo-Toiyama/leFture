## 採点のしかた(ハーネスを作るときのルール)

**各周で探索役に見せるもの**
- 今日の日付
- 地図: コース一覧(名前・学期・講義数・講義の日付の範囲)、この会話の節のタイトル(`S`)、最近20件のチャット(`P`、タイトル・日付・話題の流れ)。見え方は`CASES.md`の先頭と、`build_cases.py`の`course_map_line` / `chat_map_line`
- 画面の文脈、前のターンで開いたもの(呼び名 + タイトル + 日付)、直近の会話の原文(スレッドがあるケースと、続きの質問のケース)
- これまでの経過(`<progress>`)と、次にできること(`<next_options>`: 残りの周、開いたもの、走らせた検索、見えているがまだ開いていない呼び名)
- その周までに開いた中身、見つかった結果(台本の`opened`・`found`から、世界のデータで組み立てる)。Deep Noteの引用記号`⟦s000412-s000425⟧`は`C1/L4/s412-425`に書き換える

**選べる呼び名(JSON Schemaの`enum`)**
- 全コース`C*`と全講義`C*/L*`(講義のタイトルは見せないが、「第6回」「前の回の次」のように番号で直接行けるようにするため)
- 開いた講義のトピック`C*/L*/T*`、この会話の節`S*`、最近20件の`P1`〜`P20`、見つかった結果の呼び名(`P31`、`W1`など)
- 文字起こしの範囲`C*/L*/s…`は、開いたDeep Noteの引用か、検索結果に出たものだけ

**出力**: `reasoning` → `status`(`nothing_needed` / `enough_now` / `need_more`) → `missing` → `operations` → `goal`の順。`need_more`以外なら操作は捨てて「終わり」扱い(本番のコードと同じ)。

**操作**
- `open`: 呼び名を開く
- `find`: 出どころ(`lecture` / `chat` / `web`)と種類、検索語。`lecture.concept`は`layer`(`summaries` / `notes` / `transcript` / `all`)と`within`(`C*`や`C*/L*`)で絞れる
- `by_date`: 日付の範囲(と任意で`within`)で講義を引く

**1周の正解の判定**(`alternatives`のどれか1つに合えば正解)
- 終わるべきところで終わっているか
- `must`を全部選び、`one_of`から1つ以上選び、それ以外は`may`に入っているものだけか
- 探すときは、検索語に`query_any`のどれかが含まれているか。`layer_any` / `within_any`があれば、その中から選んでいるか(`within_any`の`None`は「絞らない」)
- 日付で引くときは、日付が一致しているか
- 根拠の種類が許されたものか、**根拠の引用が生徒の発言(または画面の選択テキスト)にそのまま含まれているか**
- 関係の種類(`direct` / `possible_link`)が合っているか
- 1周で5か所を超えていないか

**効率**: 正解の候補のうち`detour`(遠回り)を選んだ数を、合否とは別に数える。

**前の周は正しかったとして、次の周を評価する**(1つ間違えても後ろが崩れない)。
ほかに、ゴール(答えるべき項目)の中身はレポートに出して人が読む。探索役の1周ごとの時間も記録する。

## 根拠の種類(2026-09-30に決定)

`explicit_request` / `past_reference` / `on_screen` / `likely_in_course` / `needs_external_info`の5つ。
取りに行くのは、発言そのものに手がかりがあるときだけ。「どこかにあるかもしれない」では探さない。
関係(`direct` / `possible_link`)は、根拠の種類からは決めず、材料ごとに付ける。

## この後の流れ

1. **(今ここ)** ユーザーが`cases/CASES.md`を読み、GOを出す
2. 探索役のプロンプト(英語)とハーネスを作り、2.5 Flash-Lite / 3.1 Flash-Liteで各3回実行
3. 周ごとの正解率・遠回りの数・時間・よくある間違いのレポートを作る → モデルとプロンプトを決める
