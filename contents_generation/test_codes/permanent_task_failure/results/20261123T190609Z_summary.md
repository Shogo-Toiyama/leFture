# Permanent task failures (TODO #2): no audio / no speech

## Problem
- **No audio.** `/start-analysis` accepted a pre-recorded lecture whose `audio_path` was empty, so `TRANSCRIBE_MASTER` failed with "missing audio_path". Cloud Tasks then retried it on 500s, and the lecture looked stuck on "Transcribing audio".
- **No speech.** For user X, lecture 1 (not on the allowlist), the master audio was about 10 KB for 73 s. `TRANSCRIBE_MASTER` returned 0 sentences but was marked COMPLETED.
  - `CORE_EXTRACTION` then failed with "No valid transcript lines" and returned 500, which Cloud Tasks retried.
  - The task row was still being re-run 3 days after the job was created, either from Cloud Tasks retries or from the user pressing Retry.
  - The app showed the raw traceback together with a Retry button.

## Change
- **New exception.** `PermanentTaskError(code, message)` is in `app/services/helpers/task_errors.py`. It has two codes, `NO_SPEECH_DETECTED` and `AUDIO_NOT_UPLOADED`. When it is raised, `processing_tasks.error_message` is set to `"CODE: message"`, with no traceback.
- **Stop at transcription.** `TRANSCRIBE_MASTER` and `CHECK_AND_ASSEMBLE` stop when the assembled transcript has no non-empty sentence. `TRANSCRIBE_MASTER` still records the transcription cost in `usage_records`.
- **CORE_EXTRACTION backstop.** Its empty-input check now raises the same error. This covers old jobs that are retried by hand.
- **Worker response.** `_run_worker_task` marks the job FAILED immediately and returns 200, so Cloud Tasks does not retry. Other exceptions behave as before: a 500 response, and the job becomes FAILED only on the last attempt.
- **Start check.** `/start-analysis` returns 409 `AUDIO_NOT_UPLOADED` when a pre-recorded lecture has no `audio_path` and the server has no chunks. Realtime lectures are not affected: either `expected_chunks > 0`, or chunks exist when the analysis is started from another device.
- **Flutter app and webapp:**
  - They read the code from `error_message`. They show a dedicated title and explanation instead of the raw error, and hide Retry.
  - Start Over is hidden for no speech, because it would give the same result.
  - The 409 on start shows the "audio not uploaded" message.

## Test (`run_test.py`)
The test calls the production functions. DB, R2, transcription and LLM are faked. Case A reads one real `transcript_assembled.json` from R2 (read-only).

| Case | Result |
|---|---|
| A. CORE_EXTRACTION, real empty transcript (user X, lecture 1: 0 sentences) | `NO_SPEECH_DETECTED`, LLM not called |
| B1. TRANSCRIBE_MASTER, empty segments | FAILED `NO_SPEECH_DETECTED: …`, no traceback, cost recorded once |
| B2. TRANSCRIBE_MASTER, no audio_path | FAILED `AUDIO_NOT_UPLOADED: …` |
| B3. TRANSCRIBE_MASTER, with speech | COMPLETED (unchanged) |
| C. CHECK_AND_ASSEMBLE, all chunks REVIEWED but empty | `NO_SPEECH_DETECTED` |
| D1. Worker, permanent error | returns 200 body, job set FAILED at once |
| D2/D3. Worker, ordinary error | re-raised (500); job FAILED only on last attempt |
| E1. start-analysis, pre-recorded, no audio, no chunks | 409 `AUDIO_NOT_UPLOADED` |
| E2–E4. Chunks on server / realtime / audio present | pass the check |

Result: 12/12 passed in 0.20 s (dry run: 12/12).

Cost: $0. There were no LLM, transcription or Cloud Tasks calls, and nothing was written to production. The only external call was one R2 GET, in case A.
