# 自分像プロフィールの評価用データ

ロードマップ(`docs/chatbot_context_and_retrieval_roadmap.md`)の「9. 自分像プロフィール」の観察役・まとめ役・
表紙の書き直しの質を確かめるための、手で書いた台本。**まだ評価は実行していない。** 6本とも台本を書き上げた。
ユーザーが中身を見てGOを出してから、プロンプトと実行スクリプトを作り、評価を始める。

## ファイル

```
build_scenarios.py   台本の本体(ここが正本。編集するときはこのファイルを直す)
scenarios/*.json     ↑を実行して書き出したもの(生成物。直接編集しない)
```

再生成: `python build_scenarios.py`

## 1本のシナリオ = 1人の架空ユーザーの時系列

要約テストとの違いは、観察役・まとめ役が**複数のスレッド・複数の日付をまたいで**動くこと。なので1本の会話ではなく、
1人のユーザーに起きる出来事を日付順に並べる。

| イベント | 意味 | 確かめること |
|---|---|---|
| `thread` | 1つのスレッド(日付・文脈つき)。観察役がこの単位で読む | `expect_observations`: 観察に書かれるべきこと / 書かれてはいけないこと |
| `consolidate` | まとめ役を動かす地点 | `expect`: 2層の項目・覚え書き・仮説・確認待ちの「あるべき / あってはいけない / あってもよい」 |
| `user_action` | 本人の操作(違う / 残したくない / 直す / 確認トレイ) | その後の consolidate で、操作が守られているか |
| `cover` | 表紙(1層)の書き直しを動かす地点 | 欄ごとに「自動で埋める / 自動で更新 / 書き直し案だけ」が守られ、中身が傾向で書けているか |

- 期待値は文字列一致ではなく**意味で照合する**自然文。評価時に判定役(LLM)が照合し、レポートで人が確かめる。
- まとめ役を動かすタイミング(件数N)は評価の対象外。`consolidate` の位置は台本で固定する。
- `items_allowed` は「あってもなくてもよい」もの。精度の計算に入れない。
- 仮説を確かめる場面(AIが自然に聞く)は、台本ではAIのセリフとして書いておく。回答役が本当に自然に聞けるかは、
  別のテスト(回答役のプロンプト評価)で確かめる。
- 「今日」の日付は、そのイベントの直前のスレッドの日付として渡す(覚え書きの期限切れを判定するため)。
- `user_action` の対象が見つからない(まとめ役が作らなかった)ときは、`if_target_missing: "inject"` なら
  評価側でその項目をAIが作ったものとして差し込み、操作の後の振る舞いを確かめられるようにする。
  作らなかったこと自体は「上げそこね」として別に数える。
- `stored_content_must_not` は、指定した場所(項目・観察・仮説・覚え書き・ブロックした分野)の全文に、
  その語が含まれていないかを文字列で確かめる。

## 主な指標

1. **間違って上げた数**(`items_must_not` / `memos_must_not` に当たる項目ができた) ← 一番重い
2. 上げそこねた数(`items_must` ができていない)
3. 観察の段階での一般化(観察の `must_not` に当たる書き方)
4. センシティブの扱い(推測から上げない・明言は確認待ち・ブロック後は提案しない、中身を残さない)
5. 傾向と記録の区別(記録がまとめられていないか、傾向が重複していないか)
6. 本人の操作が守られているか(違う・残したくない・直す)

| t2 | 9/12 | 雑談 | 「スターシップのキャッチ見た?やばくない?」→ AIが聞くが、本人は答えず夕飯の相談へ | 惹かれた点は**不明**。推測で埋めない |
| c1 | | | まとめ役 | 項目はまだ作らない。**仮説を作る**(精密な制御に惹かれる?) |

### P2 `p2_bridge_ja` — 対立の間に入ってつなぐ役回りにやりがい

- t1 **歴史の試験対策**(義務)。薩長同盟の復習中に「歴史は正直苦手、年号覚えられない。でも龍馬が仲の悪い薩摩と長州の間に入ったところだけは好き」 → 惹かれた点 + 但し書き。「歴史に興味」は作らない
- t2 **相談**: 文化祭実行委員。演劇派と模擬店派が揉めていて間に入っている。「しんどいけど、まとまった瞬間がめちゃ嬉しい」 → 惹かれた点 + **プロジェクトの記録1件目**
- t3 **雑談**: サッカーでボランチ。「点を取るより、攻撃と守備をつなぐのが好き」 → 惹かれた点
- c1 → **傾向「対立や分断の間に入ってつなぐことにやりがいを感じる」**(根拠 t1・t2・t3)
- t4 **相談**: 文化祭の進捗(両方の代表を集めて話し合いの場を作った) → 記録2件目。前の記録と**まとめずに追記**
- t5 **AIが振った話題**: AI「歴史小説とか読む?」本人「うーん、たまに?」 → 弱い信号。「歴史好き」にしない
- t6 **雑談**: 文化祭が終わる。「結局、劇と模擬店の両方をやる形にまとまった」 → 記録3件目 + 傾向の根拠が増える
- c2 → 傾向は根拠が増えて書き直し(履歴が残る)。記録は3件が時系列で並ぶ。「歴史・幕末に興味」はない

### P3 `p3_culture_en` — 話題で一般化してよい場合 + 料理の記録

- t1: "I cook every Sunday, it's my reset." シャクシュカを作った → **本人の明言なので1回で傾向**(料理は気持ちのリセット)+ 料理の記録1件目
- t2(9/13): 「昨日」ラーメンを一から作った(記録2件目、**日付は9/12**)。Duolingoで日本語を自分から勉強中
- t3: 自分で選んだ選択科目の日本史で、範囲外の江戸の食文化を質問
- t4: アニメのおすすめの話、京都に行きたい
- c1 → **「日本の文化に興味がある」を作ってよい**(言語・歴史・食・アニメと、別々の文脈で何度も)。慎重すぎて作れない、を防ぐテスト
- t5: 餃子を作った(記録3件目)。サイドプロジェクトを3つ、概要だけ話す(ロボットアーム、家計簿アプリ、ZINE)
- t6: ロボットアームの進捗(サーボの選定)
- c2 → 料理の記録は**3件が別々**(1文にまとめない)。3つのプロジェクトは「プロジェクト」の下に記録。ロボットアームの進捗は追記

### P4 `p4_traps_ja` — 罠ばかり

- t1 **試験対策**: 量子力学の質問を大量に(「明日テスト」)→ 「量子力学に興味」にしない
- t2 「試験3つ連続でもう何もしたくない」→ 性格(疲れやすい等)にしない。覚え書きの「今の状況」(期限つき)ならよい
- t3 **センシティブ・明言**: 「実家がお寺で、自分も一応仏教徒。お盆は毎年手伝ってる」→ **確認待ち**(pending_confirm)。表紙に使わない
- t4 **センシティブ・推測**: 友達の教会のクリスマスコンサート。「みんなで歌うの楽しかった、ゴスペルの一体感がよかった」→ 宗教の項目は作らない。観察としては「大人数で声を合わせる一体感」
- t5 **健康・推測**: 「最近夜眠れない日が続いてる」→ 健康の項目は作らない
- t6 **AIが振った話題**: AI「数学好き?」本人「まあ嫌いじゃないかな」→ 弱い信号
- c1 → 有効な項目はほぼゼロ。確認待ちが1件(仏教)。宗教・健康・量子力学・数学の項目はない
- cov1 → 表紙は空欄のまま、または確認待ちを使わずに書く(仏教が表紙に出ない)

### P5 `p5_memos_en` — 覚え書きとプロフィールの区別

- t1 学習: "Numbers mixed with letters make my head explode." → **プロフィール**(記号の多い表現が負担になりやすい)+ **覚え書き**(式の前に言葉で説明)
- t2 学習: "Fewer formulas this time, I'm on my phone." → **この会話だけ**。覚え書きにしない
- t3 学習: "I always get it faster when you start with an example." → 「always」なので覚え書き(例から入る)
- t4 相談: "I'm job hunting until December, so I'm a bit scattered." → 覚え書きの「今の状況」(12月末まで)
- t5 学習: 例から入る説明に、本人がよく反応する
- c1 → 覚え書き3件(言葉で説明 / 例から / 就活中・期限つき)。「数式少なめ」は覚え書きにない。プロフィールには学び方の傾向

### P6 `p6_actions_ja` — 本人の操作と表紙のルール

- 最初の表紙: 自己紹介は**本人が書いた**(「東京の大学2年。情報系の学部で、プログラミングを勉強中。」)/ 興味は**空欄** / 将来の夢は**AIが書いたまま**
- t1 ゼミ発表がうまくいった + 「授業の課題より、自分の困りごとを解決するツールを作る方が断然楽しい」(明言)+ 時間割スクリプトの記録
- t2 新歓の司会で笑いを取った / t3 グループワークの代表で発表
- c1 → ツール作りの傾向(明言)。「人前で話すのが好き」は推測で3回あるので作ってよい(作られなければ評価側で差し込む)
- **a1 違う**: 「人前で話すのが好き」(「発表は役割だからやってるだけ」)
- **a2 直す**: ツール作りの傾向を本人が「自分や友達の不便をなくす、小さいツールを作るのが好き」に書き換え
- t4 先生に指名されてまた発表 / t5 学園祭の司会を頼まれた(「まあやるけど」)
- c2 → **同じ意味の項目を作り直さない**。直した文はそのまま
- t6 「ADHDの診断を受けていて、薬で集中できる時間が伸びた」(健康・明言)→ c3 で**確認待ち**
- **a3 確認トレイで「残さない」**
- t7 「薬の量が変わって眠い」+ 時間割スクリプトを友達に共有 → 観察役は**健康の内容を書かない**。c4 で健康を提案しない。
  「ADHD・薬・服薬・診断」の語が項目・観察・仮説・覚え書き・ブロックした分野の**どこにも残っていない**。
  直した文は変えずに、根拠(t7)だけ足す
- t8 「最初は頼まれたからだったけど、最近、人前で話すのが楽しくなってきた」(明言)→ c5 で**再提案してよい**(変化が分かる書き方が望ましい)
- cov1 → 自己紹介は**書き直し案だけ**(本文は変えない)/ 興味は**自動で埋める** / 将来の夢は**自動で更新か今のまま**(案にはしない)

## 実行

```
python run_eval.py                                  # 全シナリオ(本番の既定値: 観察役 Luna 推論なし / まとめ役 Luna medium / 表紙 Luna low)
python run_eval.py p6_actions_ja --tag try1         # 1本だけ。結果は results/try1/
python run_eval.py --consolidator-reasoning high --tag x
python generate_report.py --tag lunaD_r1            # results/lunaD_r1/report.html
python compare.py --prefix lunaA_ lunaB_ lunaD_     # 複数回の比較(揺れ・役割ごとの原価)
./run_luna_matrix.sh                                # 全Lunaの3構成 × 3回
```

採点役(`JUDGE_MODEL`)は比較の物差しなので、モデルを比べている間は変えない(今は Gemini 3.5 Flash-Lite。評価専用)。

## 結果とモデルの決定(2026-10-03)

方針(ユーザー): 必ず期待どおりに動く必要はない(気付いたら溜まっているもの)。**最優先は作ってはいけないものを作らないこと**、次に安さ。速さは要らない。

| 構成 | 観察役 | まとめ役 | 表紙 | 間違って上げた | 取りこぼし | 原価(6人分) |
|---|---|---|---|---|---|---|
| `run3_low` | Luna 既定 | 3.5 Flash-Lite low | 3.5 Flash-Lite low | 1(仏教が active) | 10 | $0.051 |
| `run3_medium` | Luna 既定 | 3.5 Flash-Lite medium | 3.5 Flash-Lite low | 0 | 6 | $0.098 |
| `lunaA_r1〜3` | Luna 既定 | Luna medium | Luna low | 0 / 0 / 0 | 2 / 2 / 3 | $0.028 |
| `lunaB_r1〜3` | Luna 既定 | Luna high | Luna low | 0 / 0 / 0 | 5 / 1 / 3 | $0.031 |
| **`lunaD_r1〜3`(採用)** | **Luna 推論なし** | **Luna medium** | **Luna low** | **0 / 0 / 0** | 3 / 1 / 2 | **$0.018** |

- 観察役は推論なしでも質が落ちず、観察役の原価が6割減った。まとめ役の high は原価が上がるだけで良くならなかった
- 残っている取りこぼしは「作られにくい」側だけ(文化祭の記録、「式の前に言葉で説明」の覚え書き、仮説の確認の報告)。方針上は許容
- luna* の p6 は、評価側の対象探し(`match_target`)を直した後に流し直したもの(B・Dの3回目だけは直す前の結果で、どちらも間違って上げた0)。直す前は、まとめ役が ADHD の話を「薬を始めてから集中できる時間が伸びた」と柔らかく書いた確認待ちを対象探しが見つけられず、「残さない」が空振りしていた。本番は本人が画面のカードを直接押すので起きない
- 費用の目安: 観察役 1スレッド約 $0.00016、まとめ役 1回約 $0.0008。バッチAPI(半額)は後で検討
