# Python 3.11 → 3.14 for the backend

Production runs `python:3.11-slim` (lefture_backend/Dockerfile). Python 3.11 has been security-only since 2024 and reaches end of life in 2027-10. Python 3.14 is in bugfix status until 2030-10 (devguide.python.org/versions, checked 2026-11-19). This run compares the production code on Python 3.11.18 (repo `.venv`) and 3.14.10 (`.venv314` here, both Homebrew builds on macOS) with the same `lefture_backend/requirements.txt`.

## Results

| `pip install -r requirements.txt` | ok | ok in 24 s, all wheels, nothing built from source |
| Resolved package versions (`pip freeze`) | — | identical to 3.11 (litellm 1.104.2, stripe 15.6.1 pins kept) |
| Import of all 64 modules under `app/` | 62/64 | **first run: `app.main` failed** (`No module named 'pyaudioop'`), 62/64 after adding `audioop-lts` |

| `test_progress_stream.py` (4 tests) | pass | pass |
| `context_and_notes_test.py`, `summary_token_trigger_test.py` | pass | pass |

| uvicorn startup with the production app, `/health`, `/billing/plans` without auth | 2.1 s, 200, 401 | same |

The two modules that fail to import on both versions (`app.services.pipeline`, `app.services.logic.lecture_segmentaion`) import names that no longer exist, and no other module imports them. They are unrelated to the Python version.

## The one required change

Python 3.13 removed the `audioop` module (PEP 594). pydub 0.25.1, used by `app/services/logic/transcription.py` to read the length of each m4a chunk, falls back to `pyaudioop`, which does not exist, so `app.main` cannot start on 3.13+ as is. Installing `audioop-lts` (0.2.2) restores `import audioop`, and the import and pydub checks then match 3.11. In `requirements.txt` this can be added as `audioop-lts; python_version >= "3.13"`, which leaves the 3.11 image unchanged.

## Not covered

- m4a decoding through ffmpeg: ffmpeg is not installed on this PC. The Python side (`audioop`) is covered by the WAV check. ffmpeg itself comes from Debian in the image and does not depend on the Python version.
- The Docker image (`python:3.14-slim`, apt `ffmpeg`, `nltk.downloader`) was not built: Docker is not installed here.
- Live provider calls, Cloud Tasks, Firebase push, R2, Stripe/RevenueCat webhooks, and a real chat turn or lecture pipeline run. Google ADC is missing on this PC, so a stand-in credential was used only to construct clients at import time.
- Latency: import time was 3.0 s on 3.11 and 2.1 s on 3.14, but the 3.11 run came first with cold caches, so this is not a measured speedup.

## Cost

No model API calls. Model cost $0. One read-only Supabase query per Python version.

A no-traffic revision `lefture-00279-kiy` (tag `py314`) was built from `python:3.14-slim` with `audioop-lts` 0.2.2 and the nltk punkt data. It started cleanly, `/health` returned 200, and one chat turn completed on it (Haiku 5.5, first token 4.5 s, done 6.0 s, $0.0025, no retrieval).

The lecture pipeline could not be tested on the tagged revision. Processing is driven by the `processing_tasks` database trigger, which calls `/webhook/orchestrator` at the production URL, so every worker step after `/start-analysis` ran on the 3.11 production revision. The pipeline will be checked right after the production rollout instead, with the previous revision `lefture-00276-w2q` kept for rollback.
