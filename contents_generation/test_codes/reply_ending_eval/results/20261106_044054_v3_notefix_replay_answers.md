## まず、2つの役割の違い

- **静的型付け**：「変数の型は定義時に固定され、型チェックは実行前に行われる」という**言語の性質**（TYPING5で話した「箱の型が固定」）
- **型推論**：「型を書かなくても、コンパイラが右辺などから型を決めてくれる」という**書き方の便利機能**

```
静的型付け → 「型はいつ決まって、いつチェックされるか」
型推論    → 「型を誰が書くか（人間？コンパイラ？）」
```

## 2つは組み合わせられる

型推論は**静的型付けの言語に多い**ですが、同じものではありません。

```
count := 3      ← Go（静的型付け＋型推論）
                  型推論で int に決まる → 以後は int 固定
count = "hi"    ← ❌ エラー（静的型付けのチェック）
```

ここでは、型推論が「**int という型をコンパイラが見つけてくれた**」役割、静的型付けが「**その型を固定して、実行前にチェックする**」役割を担っています。

## 授業での位置づけ

先生が「型推論を使っても変数の型は固定される」と強調していたのは、**型推論が静的型付けの前提を崩さない**、という意味でした。つまり、型推論は静的型付けを成り立たせるための道具の一つ、と考えると分かりやすいです✨

テストでは、「**型推論は型を書く手間を省く仕組み、静的型付けは型が固定されて実行前にチェックされる性質**」と分けて書けると安心ですよ！
