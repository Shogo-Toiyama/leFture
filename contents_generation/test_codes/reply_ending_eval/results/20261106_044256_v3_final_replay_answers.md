## 型昇格（Type promotion）とは？

**型昇格**は、**狭い型を広い型に自動で変換すること**です。変換しても値が欠けないのがポイントです。

小さなコップの水を大きなバケツに移すイメージです。水はこぼれません！🪣💧

```
  int（小さいコップ） ──昇格──▶ double（大きいバケツ）
        5              ──────────▶      5.0   ✅ 何も失われない！
```

---

## 具体例：`int` と `double` の足し算 🧪

```cpp
int i = 5;
double d = 3.14;
std::cout << i + d;   // i が double に昇格されてから足される
```

`i + d` を計算する直前に、コンパイラが `i` を `double` に自動で変換します。だから計算結果は `double` になります。`double` はすべての `int` の値を表せるので、この変換は安全です。

---

## どの型に合わせるか？コンパイラの判断ルール 🎯

C++では、次の優先順位を上から順に調べて、最初に当てはまったルールで変換先の型が決まります。

1. どちらかが `long double` なら、もう片方を `long double` に変換
2. それ以外で、どちらかが `double` なら、もう片方を `double` に変換
3. それ以外で、どちらかが `float` なら、もう片方を `float` に変換

`i + d` では、ルール2が当てはまるので `i` が `double` になります。

---

## 強制変換（coercion）の中での位置づけ 👨‍👩‍👧

型昇格は、自動で行われる型変換（強制変換）の一種です。強制変換のすべてが昇格というわけではありません。

```
強制変換（自動の型変換）
 ├─ 昇格 🌱    狭い → 広い、値が失われない（int → double）
 └─ 縮小 ⚠️    値が失われるかもしれない（int → bool など）
```

たとえば `int a = 5;` のあとに `if (a)` と書くと、`int` が `bool` に自動で変換されます。これは強制変換ですが、値を保つ変換ではないので、昇格ではありません。

---

## 試験対策のポイント 📝

- **昇格**：自動で行われ、狭い型から広い型へ。値は失われない
- **強制変換**：自動で行われる変換全般。値が失われることもある
- 教科書の定番例は `int` → `double` です。`int` → `float` は、`float` がすべての `int` を正確に表せないので、きれいな昇格例とは言えません

---

まとめると、**型昇格は「値を失わずに、狭い型を広い型へ自動で広げる」変換**です。`int + double` の計算で、なぜ `int` が自動で `double` になるのか、イメージできたはずです！✨

## 結論：Cat と Feline は別の型

Feline も Cat も **struct** なら、Go では「**名前が違う別の型**」です。だから **No** で合っています。

Go では、型は**名前で区別**されます。`Feline` と `Cat` は中身が同じ形でも、別々に宣言された名前付きの型なので、直接代入できません。

```go
type Feline struct{ name string }
type Cat struct{ name string }

var f Feline = Cat{name: "tama"}          // ❌ コンパイルエラー（名前が違う別の型）
var f Feline = Feline(Cat{name: "tama"})  // ✅ 明示的に変換すればOK（中身の形が同じ）
```

2行目のように**明示的な変換**が必要なのが、ポイントです！ 🔑

## 「親子じゃない」と言える理由 🙅

Go には `extends` のような継承がないので、struct どうしに**サブタイプの関係はできません**。Cat が Speak を持っていても、それで Feline の子になるわけではありません。

```
Feline（struct）    Cat（struct）
   ↑ 親子ではない（別々の名前付きの型）↑
```

## 補足：もし Feline が interface なら話が変わります

前のターンで、Feline が interface の場合の話もしました。その場合は「Speak() を持つ Cat は、Feline を満たす」と判断されます。問題文で Feline が **struct** と書かれているなら、今回の答え（No）がそのまま使えます。

テストに向けて、「Go の名前付き型はどう区別されるか」と「interface は構造で満たされる」の2つをセットで覚えておくと、この手の問題に強くなりますよ！💪

## 結論：No で合ってる！🙆‍♀️

FelineもCatも**名前のある struct（名前付きの型）**なので、Go ではそれぞれ**別の型**として扱われます。名前が違うと、中身が似ていても親子の関係にはなりません。

```
Feline（struct）  ──── 親子の矢印 ❌ ────  Cat（struct）
   名前が違う → 別の型 🆚
   継承の宣言もない → 親子にならない
```

## 中身が同じでも「そのままは代入できない」💡

Go では、フィールドが全く同じ2つの struct でも、名前が違えば代入はそのままできません。ただし、**明示的な変換**をすれば使えます。

```go
var f Feline = Feline{Name: "Tama"}
var c Cat = Cat(f)   // OK：中身が同じなら明示的に変換できる ✅
// var c Cat = f     // NG：名前が違うので、そのままの代入はエラー ❌
```

つまり「**親子として自動で置き換えられる（サブタイプ）**」わけではなく、「**手動で変換して別の型に作り直す**」イメージです。
