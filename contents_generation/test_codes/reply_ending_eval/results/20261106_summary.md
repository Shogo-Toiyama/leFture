# Reply ending eval — summary (2026-11-06)

**Question:** The answerer (Haiku 5.5) ends almost every reply with an unrequested next-topic proposal, quiz, or guiding question. Can a prompt change stop that while keeping the follow-ups that are actually needed?

**Baseline:** the production replies stored in Supabase (`chat_messages`). The old prompt was not re-run.
**Method:** `replay.py` replays the answerer only, on production turns whose retrieval returned no materials. It uses the production router decision, the summary blocks that existed at that moment, attachments with the same full/summary visibility, the screen page, and the reply quote. The rebuilt input matches production closely: the estimated/actual input-token ratio was 0.87–0.88 on all 6 cases, the same as the estimator's normal error.

## Production snapshot (2026-11-05 00:00 JST → 2026-11-06, 49 replies, 4 threads)
- Every reply ended with some call to action: 49/49.
- Unrequested next-topic proposal / quiz / guiding question: 35/49 (71%).
- The same quiz was repeated 2–3 times in a row while the student asked other things (A21→22→23, A42→43→44, A46→47→48).

## Prompt changes (final = v4)
- `chat_answer_prompt.txt` line 9: replaced "Close with … ready to continue!" with "end on the answer or a short warm line, not on a next step".
- `chat_answer_prompt.txt` HOW TO RESPOND: new "Ending the reply" rule. No next-topic suggestion, quiz, check-in, or invitation, except in three cases:
  1. information they must supply;
  2. they asked you to lead step by step;
  3. graded work where the next move is theirs.
  Concept questions are answered and left there. A question inside a quoted earlier reply is part of the quote.
- `chat_answer_turn_prompt.txt`: "Let's finish this together!" → "side by side on the question in front of you: Let's untangle this together!", plus a one-line ending reminder.

A48 is still the exception. The student's message quotes the earlier reply, and the quote's context includes "`count := 3` の型はどうなると思いますか？". The two earlier replies asked the same question. Correcting the misread conversation note (below) did not fix it.

**Side finding (not fixed):** the conversation note for thread 886879 says 「概念を理解できているかを確認する方針で説明する」. The student actually said the *test* checks concept understanding, so the summarizer turned it into a standing instruction for the AI to check understanding.

## Cost / latency
Total spend for this experiment: $0.016 (v1) + $0.010 (v2) + $0.018 (v3) + $0.005 (note fix) + $0.016 (v3_final) + $0.008 (v4) = **$0.073**. This is Haiku 5.5 at $0.10/M input and $0.50/M output, per the `llm_unified.py` billing table.
Latency matched production modes: TTFT about 0.6–3.4 s at effort low and 6–12.7 s at effort high. The change adds about 360 input tokens per turn.
