# Review Cards scroll reset during a horizontal swipe

The Flutter widget test mounted the production `ReviewCardsViewerPage` with two
synthetic content cards. Provider overrides supply the fixture data locally.
To run the current regression test from `user_interface`, use
`flutter test --no-pub --reporter expanded ../contents_generation/test_codes/review_card_swipe_scroll/review_card_swipe_scroll_test.dart`.
The test now expects the offset to be preserved and fails on this baseline.

| Measurement | Result |
| --- | --- |
| Vertical offset after scrolling | 200.0 logical px |
| Vertical offset during the first rendered horizontal drag frame | 0.0 logical px |
| Vertical offset after cancelling the pointer gesture | 0.0 logical px |
| Same `ScrollableState` before and during the drag | No |
| Committed card | 2 / 3 throughout |
| Flutter test result | Passed, runner reached completion at 00:01 |

At drag start, the viewer replaces the settled content card with an animated
stack. The outgoing content card's scroll view mounts again in that stack.
It has no explicit controller, initial offset, or PageStorage key for restoring
the outgoing card's vertical position.

No external API calls, LLM tokens, or API charges. This was a local widget test
using the Flutter test engine.
