# Web follow-up router replay

The experiment exercised the production router function, LiteLLM transport, output normalization, and billing. Each variant received 16 synthetic Japanese and English cases and the same one saved production follow-up. The saved follow-up reused its chat text and preceding messages with generic course labels. The original production response and its stored routing decision stayed untouched. All variants used the production reasoning-effort setting. The script ran mock and schema validation before each live candidate.

This evaluated routing only and incurred no Web search or answer-generation charges. TTFT and reply tone are not applicable to this non-streaming classification test.

The saved reply preceding the original failure was 780 characters. The topic began at character offset 545, within the router's 1,200-character per-message history limit. The priority candidate places the factual-follow-up distinction before general classification and limits the rule against searching on continuations to facts already supplied. The first rule was appended lower in the retrieval instructions and did not recover the saved case.

The priority candidate was designed after inspecting the first round and tested once per case. Its result supports evaluation as the next candidate without establishing its general production error rate. No production router prompt or model setting was edited. Results contain routing labels, measurements, and aggregate metadata only.
