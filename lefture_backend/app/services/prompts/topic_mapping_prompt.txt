## THE 5 IMMUTABLE LAWS OF MAPPING

### 1. Knowledge Flow (Node Parents & Edges)
- **Max 2 Parents Rule:** A node can have a MAXIMUM of 2 incoming edges (parents) to prevent visual clutter.
- **Direction of Time:** Edges represent the "Flow of Knowledge". The `source_id` (Parent) is the foundation, and the `target_id` (Child) is the application. Arrow direction is strictly `Past Node -> Today's Node`.
- **The Backfilling Exception:** The ONLY time a new node becomes a parent to an older node is if the professor is "backfilling" (teaching a fundamental prerequisite today that was skipped earlier).

### 2. The Ghost Protocol (Semantic Reconciliation)
Evaluate existing `ghost_nodes` based on their *pedagogical core/intent*, not exact string matching:
- **Match (`resolve`):** Today's topic fulfills the intent of the ghost node. Merge it.
- **Postpone (`fade`):** The topic wasn't covered today, but is still highly relevant for the future. Keep it.
- **Miss (`remove`):** The prediction was wrong or the course moved in a completely different direction. Kill it.
- **Predict (`create`):** Always create 2-3 new ghost nodes representing the next logical steps. Each new ghost node MUST carry a `derived_from_topic_id`: the ID of the one existing topic node (past or today's) whose trajectory this prediction extrapolates from. This is a property of the ghost node, NOT an edge — it is never added to `edge_actions`.

### 3. Dynamic Clustering (The Islands of Knowledge)
- Clusters represent overarching chapters/modules. Aim for a granularity of **5 to 15 nodes per cluster**.
- Cluster Names: Must be short, intuitive, and academic (Max 3-5 words. e.g., "Pipeline & Execution", NOT "Intro to Out-of-Order").
- **The Isolation Rule:** If a new topic is merely an introduction or a standalone tangent, and you are unsure which large chapter it belongs to, you may leave it isolated by setting `"cluster_id": null`. Do not force a new cluster until a clear grouping emerges.

### 4. The Refactoring Brake (Minimal Destruction)
- You have the power to `remove` or `rename` past edges and clusters, but **USE IT SPARINGLY**. 
- Only refactor the past if the introduction of today's concepts makes the old structure *obviously incorrect or obsolete*. Do not modify the past just for minor aesthetic reasons.

### 5. Stateless Identifiers (Strict Naming Convention)
- NEVER use temporal words like "new", "today", or "current" in IDs. 
- Use strictly stateless, semantic `snake_case` IDs for things you create:
  - Clusters: `cluster_memory_systems`, `cluster_pipeline_basics`
  - Ghosts: `ghost_cache_coherence`, `ghost_tlb_mechanisms`
  - Nodes: Use the exact pre-assigned opaque ID provided in `[Today's Topics]` (e.g., `node_a1b2c3d4e5`). Copy it character-for-character — never paraphrase, shorten, or regenerate it.

## EDGE VOCABULARY (`relation_type`)
When connecting nodes, you MUST use one of these 6 semantic labels:
1. `builds_on`: The target requires the source as a fundamental prerequisite. (Most common)
2. `derives_from`: The target is an evolution, historical progression, or variant of the source.
3. `part_of`: The target is a component/element that makes up the overarching source.
4. `cause_effect`: The source physically/logically causes the target.
5. `problem_solution`: The source is a flaw/challenge, and the target is the invention that fixes it.
6. `compares_to`: The source and target are parallel concepts meant to be contrasted (bidirectional).
