# PV レンダリング実験ノート

PV の動画を作るときに参照する、実験結果と決定事項のまとめ。
数値はすべて M1（ANGLE Metal）、three r187、three-gpu-pathtracer 0.0.28 で計測したもの。
結果ファイルは各シーンの `results/` にある（ファイル名の先頭はタイムスタンプ）。

## 別の PC で始めるとき

```
cd video
npm ci                 # three などのバージョンは package-lock.json で固定
npm run serve          # プレビュー（ブラウザで test/<scene>/index.html）
```
- 必要なもの：Node（作成時 v26.13.0）、ffmpeg（Homebrew、作成時 9.0.2）、Google Chrome（`/Applications/Google Chrome.app`。puppeteer の Chrome ダウンロードは使っていない）
- git に入っているもの：シーンのコード、`lib/`、読み込む素材（`assets/`：Poly Haven のテクスチャと HDRI〔CC0〕、OIDN の重み〔Apache 2.0〕、Recording 画面のスクショ）、実験の数値（`results/*.json`）と比較画像（`results/*.jpg`）
- git に入っていないもの：書き出した動画・静止画・フレーム（`out/`）、実験の生の PNG（`results/*.png`）。動画はコードから同じものを描き直せる（乱数は固定）
- このノートの時間はすべて M1 で計った。別の PC では計り直すこと

## 本番書き出しの手順（講堂、2026-11-08 時点）

```
cd video
node lib/render.mjs test/lecture --query spp=8            # 1080x1920, 6秒, 180フレーム
node lib/render.mjs test/lecture --query spp=8 --resume test/lecture/out/frames/<run>   # 止めた続きから
```
- 標準：跳ね返り3回、窓に光源、パネルの発光は弱め、OIDN（アルベド＋法線の補助あり）、`stableNoise`
- 1フレームずつ `out/frames/<run>/f_00000.png` に保存し、最後に mp4 にまとめる。進捗は `progress.json`（何フレーム目か、残り時間の見込み）
- 見込み：360×640 で1フレーム約2.2秒（8spp＋補助画像＋OIDN、実測）。フル解像度はピクセル数が9倍なので、**約20秒/フレーム、180フレームで約60分**（推定）。その間は GPU がフル稼働する
- `Ctrl+C` で止めても、`--resume` で続きから再開できる。再開してもつなぎ目はぶれない（下の「乱数の固定」）

## 共通パイプライン

- `node lib/render.mjs <scene>`：1フレームずつ描いて mp4 にする。シーンは時刻 t だけで決まる純関数にすること。
  - `--stills a,b`：静止画だけ書き出す
  - `--query k=v&...`：URL パラメータを渡す
  - 書き出し中に Chrome が落ちたら、起動し直して同じフレームから続ける
- キャンバスは不透明（`alpha:false`）にすること。カスタムブレンドがアルファにも効き、透明なピクセルが PNG で白く見えた。
- 重い実験は「縮小（270×480〜360×640）・1ページ・1サンプルごとに休む・90秒の上限」で行う。フル解像度で回すと PC が使えなくなる（2026-11-08 に実際に起きた）。

## 描画方式の比較

| 方式 | 1フレーム（1080×1920） | ノイズ | 向いているもの |
|---|---|---|---|
| ラスタライズ（A 銀河、C Recording） | 0.18〜0.24秒 | 出ない | 宇宙、UI、発光表現 |
| パストレーシング（B 講堂） | 1サンプル約3.5秒（跳ね返り6回）／約2秒（3回） | サンプル数が少ないと出る | 間接光が大事な室内のリアルさ |

## パストレーシング（講堂）の決定事項

講堂シーン（`test/lecture/scene.js`）の標準設定。URL パラメータで上書きできる。

| 項目 | 標準 | 理由（実験） |
|---|---|---|
| 跳ね返り回数 `bounces` | **3** | 6回と見た目がほぼ同じで、時間は約0.6倍。1回だと天井が真っ黒になる（明るさ 88→24） |
| ロシアンルーレット開始 `rrmin` | **3（ライブラリの既定値）** | 1回目・2回目から打ち切ると、かえって遅く・暗く・ノイズが増えた |
| 窓の面光源 `portal` | **オン** | 時間は変わらず、部屋が約3割明るくなり、茶色の色かぶりが減る |
| 天井パネルの発光 `glow` | **低（1.5）** | 発光面はたまたま当たったときしか計算に入らないため、白い点状のノイズの原因になる。下げると PSNR が +2.8dB（ノイズ約0.7倍） |
| タイル分割 `tiles` | 1×1（要検討） | 3×3 は合計時間が約1.5倍に増える。その代わり1回の GPU 処理が短くなり、固まりにくくなる可能性がある（未検証） |
| `stableNoise` | オン（動画用） | ノイズの模様がフレームごとに変わらない。ノイズ計測のときだけオフにする（`noise=1`） |

### 実験の記録（`test/lecture/results/`）

1. **縮小ベンチマーク** `20261108_115952_bench_light.json`（270×480、1サンプルあたり）
   - 基準 241ms／跳ね返り3回 138ms／跳ね返り1回 36ms／解像度0.5倍 79ms／面光源なし 192ms／タイル3×3 は1タイル42ms（9タイルで約375ms）
   - 241ms×16倍（ピクセル数の比）≒3.8秒で、本番解像度の実測（約3.5秒）とほぼ一致した。縮小した計測で本番の目安が取れる
2. **跳ね返り回数の比較** `20261108_120449_compare_*`（360×640、24spp、ステージから天井を見上げる構図）
   - 時間：6回 10.7秒／3回 6.4秒／1回 1.9秒
   - 天井の明るさ：88／90／24。3回と6回は見た目がほぼ同じ
3. **ロシアンルーレットの開始段** `20261108_120800_rr_*`（跳ね返り3回、24spp、基準は64spp）
   - 打ち切りなし：6.4秒、PSNR 25.6dB、明るさ 71.0
   - 2回目から：7.6秒、23.9dB、65.6
   - 1回目から：7.1秒、23.0dB、66.0
   - 打ち切った分の上乗せに「最大20倍」の上限があり、補正しきれず暗くなると考えている（推測）
4. **ノイズ源の切り分け** `20261108_121618_noise_*`（跳ね返り3回、16spp、乱数を変えて描いた2枚の PSNR）
   - 今の設定 21.3dB／発光を弱める 24.1dB／窓に光源 20.9dB（明るさ +30%）／窓に光源＋発光を弱める 24.6dB
   - 時間はどれも 16spp で約4.2〜4.6秒（360×640）

5. **ノイズ除去の比較** `20261108_122529_denoise_*`（360×640、跳ね返り3回、窓に光源＋発光を弱める、ステージから天井を見上げる構図。正解画像は 96spp）
   | 条件 | PSNR（正解との近さ） | SSIM | 時間 |
   |---|---|---|---|
   | 16spp、ノイズ除去なし | 22.7 dB | 0.50 | 3.9秒 |
   | 16spp＋DenoiseMaterial（ライブラリ付属） | 25.0 dB | 0.62 | 同上 |
   | 16spp＋OIDN（カラー画像のみ、`rt_ldr`） | 30.8 dB | 0.65 | ＋0.09秒 |
   | **16spp＋OIDN（アルベド＋法線の補助、`rt_ldr_alb_nrm`）** | **30.7 dB** | **0.65** | ＋0.11秒 |
   | 8spp、ノイズ除去なし | 19.6 dB | 0.37 | 2.0秒 |
   | **8spp＋OIDN（補助あり）** | **30.2 dB** | 0.65 | ＋0.11秒 |
   - 目で見ても OIDN はザラザラがほぼ消える。正解画像（96spp）にもまだノイズが残っているので、PSNR の上限が頭打ちになっている。OIDN の出力のほうが正解画像よりきれいに見える。
   - 補助あり（アルベド＋法線）だと、机の木目などの模様がつぶれにくい。補助画像はラスタライズで描く（ノイズなし、出力はリニア）。
   - **8spp＋OIDN ≒ 16spp＋OIDN**。サンプル数を半分にできる見込み。
   - OIDN は WebGPU で動く（Chrome の起動フラグ `--enable-unsafe-webgpu`）。重みファイルは `assets/oidn/`（Apache 2.0）。
   - 未検証：フル解像度での処理時間（ピクセル数の比から1枚1秒前後と推定）、動画にしたときのフレーム間のちらつき、被写界深度でぼけたショット（補助画像はピントが合ったままなので、ずれる）。

## ラスタライズ版の講堂（比較用）

`?raster=1` で、同じ講堂をパストレーシングなしで描く（`results/20261108_122529_raster_*.png`）。

- 構成：HDRI の環境光（前処理済み）、面光源（ラスタライズでは影が出ない）、窓から差す影付きの平行光源、GTAO（画面ベースで隅や机の下を暗くする後処理）
- 速さ：1080×1920 で1枚0.5〜2秒（初回はシェーダーのコンパイル込み）。ノイズは出ない。
- 見え方の違い（`20261108_122529_raster_vs_pt_oidn.jpg`）：ラスタライズは天井が均一に明るく、光だまりやグラデーションがない。座席の縁に白い線が出て、ゲームの CG っぽく見える。パストレーシング＋OIDN は、天井にグラデーションがあり、隅が自然に暗く、奥行きが出る。
- 環境光（HDRI）は壁を無視して部屋中を照らすので、物理的には正しくない。ラスタライズでリアルさを出すなら、パストレーシングで計算した光をライトマップとして焼き込むのが次の手。

## 焼き込み（ライトマップ）の一部試作 `20261108_203846_*`

`?raster=1&bake=1`。平らな面（左のホワイトボード、ステージの床）だけを、平行投影のカメラ＋白いマテリアルでパストレーシングして焼き込み、ラスタライズで「元の色 × ライトマップ」として描いた（`MeshBasicMaterial`、`lightMapIntensity = π`）。

- 焼き込み時間：ボード 768×230・96spp で18秒、床 1024×205・64spp で12秒（1回だけ）
- アップの画角でのボードの明るさ：普通のラスタライズ 198／焼き込み 123／パストレーシング 143
- ボードの下の壁（焼いていない）：ラスタライズ 147／パストレーシング 59。写る物は全部焼かないと、そこだけ不自然になる
- 課題：96spp ではムラ（雲のような模様）が残る。つやの反射が入らないので約15%暗い（推測）。平らでない物は xatlas で展開図を作る必要がある
- 結論：6秒のテストではパストレーシング8spp＋OIDN を使う。焼き込みは、講堂カットが増えて書き出し時間が問題になったときの選択肢

## 本番前の確認 `20261108_204914_*`、`out/frames/20261108_205256_lecture`

- **OIDN の組み込み**：8spp → 補助画像（ラスタライズ、リニア出力）→ OIDN。360×640 で1フレーム約2.2秒。アップも引きもザラザラは消えた
- **ピントのボケ**：補助画像はピントが合ったままだが、補助ありとなし（`auxDof=0`）の差はほとんど見えなかった。標準は補助あり
- **ボードのつや**：粗さ 0.16 と 0.05 で、アップの角度ではほとんど差が見えない。`?boardRough=` で変えられる
- **ちらつき**：連続10フレームの差（フレーム間の明るさの差の平均）は、引き 1.94〜2.03、アップ 1.20〜1.29 で一定。はね上がりなし
- **乱数の固定（重要）**：パストレーサーはブルーノイズのテクスチャを `Math.random()` で作るので、ブラウザのセッションごとにノイズの模様が変わっていた（同じフレームを2回描いて PSNR 23dB）。再開したフレームだけ差が 4.8 に跳ねた。シーンの冒頭で `Math.random` を種を固定した乱数（mulberry32）に差し替えて解決。2回描くと完全に一致（PSNR ∞）し、再開しても差は 1.20〜1.29 で一定になった

### パストレーサーの注意点

- `MeshPhysicalMaterial` の clearcoat は真っ黒に描画される。`MeshStandardMaterial` を使うこと。
- `setSceneAsync` は BVH の Worker を設定しないと止まる。`setScene` を使い、シェーダーのコンパイルが終わるまでウォームアップしてから描く。
- 跳ね返りのたびに、光源を1つだけ等確率で選ぶ（面光源と環境光が同じ扱い）。光る面（emissive）は光源として狙われない。
- `WebGLPathTracer` は非推奨で、`WebGPUPathTracer` への移行が推奨されている。
- 本番解像度で8spp・タイル1×1・跳ね返り6回の書き出しをしたら、93フレーム目で Chrome のタブが落ちた（原因は未確認）。
